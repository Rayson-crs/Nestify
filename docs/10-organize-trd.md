## 1. 文档目的

本文定义 Nestify「整理」模块的产品目标、设计理念、用户流程、规则模型、预览模型、执行边界和验收标准。

## 1.1 当前实现状态（2026-09-12）

本节用于区分 TRD 目标和当前代码实际能力，避免把已设计但尚未落地的能力当成已完成能力。当前页面布局以“重复”和“改名”模块为交互基准，但整理不复用规则页面的规则集，保留自己的业务步骤：

```text
1 选择文件夹
  -> 2 加载目录并用输入助手筛选
  -> 3 设置整理规则并预览
  -> 4 确认执行
```

| 能力 | 当前状态 | 说明 |
| --- | --- | --- |
| 整理四步向导 | 已实现 | 第一步只选择文件夹；第二步加载目录并使用输入助手筛选；第三步设置规则和预览；第四步确认执行。步骤条、返回和确认布局参考重复、改名模块。 |
| 资料库、目录、搜索勾选范围 | 部分实现 | 当前整理页面固定从文件夹开始，文件夹必须落在某个资料库根目录内；底层快照仍保留 `library`、`directory`、`selection` 兼容能力，页面不提供规则页的搜索勾选入口。 |
| 冻结整理快照 | 已实现 | 生成快照 ID、fingerprint、对象统计和最大层级，预览使用快照而不是边执行边读盘。 |
| 整理预览 | 已实现 | 使用整理页面传入的独立规则草稿，并复用通用 `planRuleset`/`ChangePlan` 作为底层求值和计划格式；返回动作、对象类型、阶段、风险、规则 ID、原因和解释。 |
| 预览与确认分离 | 已实现 | 第 3 步实时刷新基础预览，点击“生成预览并进入确认”后进入第 4 步；第 4 步提供最终勾选、执行和回滚。 |
| `quarantine` 处置 | 已实现 | 整理链路复用通用计划执行器；删除动作保持禁用，不把删除作为普通整理动作。 |
| 通用执行与回滚入口 | 部分实现 | 整理复用 `plan.execute`、`plan.rollback` 和任务页，执行时使用文件夹匹配到的资料库；尚未形成独立的整理任务上下文。 |
| 快照持久化与过期校验 | 未实现 | 当前快照主要保存在 runtime 内存，重启后的恢复、执行前 fingerprint 校验仍需补齐。 |
| 整理专用规则编辑器 | 已实现基础版 | 整理页面拥有独立于规则页面的规则草稿；主页面只显示“设置规则”入口，规则列表在弹窗中维护。支持启用、名称、对象类型、处理范围、输入助手条件、多动作顺序、动作增删和规则上下移；列表顺序代表优先级。高级 JSON 和原因输入不作为普通用户入口。 |
| 整理动作链 | 已实现基础版 | 一条规则可以按顺序执行多个移动、文件改名、文件夹改名或拍平动作；后续动作读取虚拟目录中的最新路径，父目录变化会同步到子项。隔离区仍由安全处置链路支持，但不作为普通动作下拉项。 |
| 虚拟目录树 / 树对比 | 未实现 | 当前已有预览行和计划表，但还没有原始树与目标树的可视化对比。 |
| 操作账本与事件时间线 | 未实现 | 通用 job 记录可承载基础结果，整理要求的依赖、前后 fingerprint、逐步事件和恢复条件尚未完整落地。 |
| 依赖感知回滚 | 未实现 | 当前回滚仍复用通用计划回滚，目录合并、跨盘移动、父子依赖和外部变更保护需要独立实现。 |

因此，“页面和基础预览主链路”可以继续验收；“完整整理事务、复杂嵌套规则和可审计回滚”仍然不能宣称完成。

整理模块的目标不是提供一组固定的“按扩展名移动”按钮，也不是让系统猜测文件内容或业务含义，而是：

```text
读取原始目录树
  -> 用户用可理解的规则描述目标结构
  -> 系统在虚拟目录树中模拟全部变化
  -> 用预览解释每个对象为什么被这样处理
  -> 用户逐项确认
  -> 生成并执行可回滚的文件操作计划
```

本文重点解决以下问题：

1. 文件夹名称无意义、数字化或异常时，如何根据明确的文件名规则整理并改名。
2. 文件夹改名、移动、合并后，子文件规则如何继续命中。
3. 多组规则如何组合，同时避免前面的动作让后面的规则失效。
4. 默认操作要简单，复杂需求又不能被固定模式限制。
5. 用户必须在执行前看清原位置、目标位置、动作、命中规则和风险。
6. 整理执行必须生成可追溯任务，完整记录实际操作和可逆向恢复的信息。
7. 用户可以从任务详情查看每个变化，并对已成功且仍满足安全条件的操作发起回滚。

## 2. 产品定位

整理是一个**目录结构变换工具**。

它处理的是：

- 文件夹识别
- 文件识别
- 文件夹创建
- 文件夹重命名
- 文件夹移动
- 文件移动
- 文件名修改
- 目录合并
- 空目录处理
- 冲突检查

它不负责：

- 读取图片、视频或文档内容并推断语义
- 根据媒体内容猜测文件名
- 自动调用 OCR、视觉模型或大模型分类
- 在用户没有明确配置时猜测目录应该叫什么
- 在没有预览和确认的情况下直接整理
- 把复杂配置隐藏为用户无法解释的“智能评分”

可以使用的判断依据仅限于索引或文件系统可确定的结构信息：

- 文件名和扩展名
- 文件或目录类型
- 当前路径、父路径和相对路径
- 当前层级
- 文件大小、时间等基础属性
- 父目录名称和属性
- 子文件数量、子目录数量和子项扩展名分布
- 名称是否符合纯数字、UUID、固定模式等确定性条件
- 用户明确配置的名称映射、关键词和模板

核心原则：

> 系统可以根据结构判断“放到哪个文件夹”，但不能在没有证据时猜测“文件应该叫什么”。

## 3. 设计理念

### 3.1 预览优先

预览不是执行前的附属表格，而是整理模块的主要产品能力。

规则是否正确，不以规则输入框中写了什么为准，而以虚拟目录树中最终会发生什么为准。

用户在第 3 步编辑规则时就应该看到：

- 哪些对象被命中
- 原始位置是什么
- 最终位置是什么
- 是移动、重命名、合并、创建还是保持不变
- 为什么命中
- 哪些规则共同作用
- 是否存在冲突或需要人工确认

### 3.2 简单入口，高级扩展

默认入口使用可视化的“当……时，执行……”结构：

```text
当：扩展名为 jpg、png
执行：移动到图片文件夹
目标目录：优先使用当前目录下已有的“图片”文件夹
文件名：保持原名
```

复杂用户可以展开：

- 父目录条件
- 子项条件
- 多条件 AND/OR
- 目录命名来源
- 子项继续处理
- 目录合并
- 文件名模板
- 规则阶段
- 冲突策略

二者必须使用同一份底层规则模型。简单入口不是另一套能力，点击“高级设置”后应能看到系统为简单配置生成的完整规则。

### 3.3 结构事实优先，推断必须显式

以下属于结构事实，可以直接作为默认条件：

- 名称是否为纯数字
- 名称是否符合 UUID
- 是否为文件夹
- 子文件数量
- 是否包含指定扩展名
- 文件名是否包含用户指定关键词

以下属于启发式判断，只能作为可选条件并在预览中标注：

- 疑似乱码
- 疑似随机字符串
- 疑似无意义目录名
- 目录的主要文件类型

启发式命中时，预览必须说明判定依据，不能把它显示成绝对事实。

### 3.4 规则计算和真实执行分离

规则计算期间不得修改真实文件系统。

正确流程：

```text
原始快照 S0
  -> 虚拟状态 V0
  -> 计算规则和虚拟变换
  -> 最终虚拟状态 Vn
  -> 生成 ChangePlan
  -> 用户选择和确认
  -> 执行前校验
  -> 一次性执行
```

禁止流程：

```text
命中 A -> 立即改真实目录
重新扫描磁盘
命中 B -> 再执行 B
```

后者会导致 A 改名或移动后，B 无法根据原结构命中，也会让预览和执行结果不一致。

### 3.5 整理任务是审计和恢复单元

整理任务不是一个只有“成功/失败”状态的进度条，而是一次完整的文件系统变更事务记录。任务必须能够回答：

- 什么时候执行的、整理根目录是什么；
- 使用了哪一版筛选条件、规则组和全局选项；
- 预览基于哪个原始快照，用户最后勾选了哪些操作；
- 实际执行了哪些目录创建、移动、改名、合并或清理动作；
- 每个动作原来在哪里、后来在哪里、由哪条规则触发；
- 哪些动作成功、跳过、失败，失败原因是什么；
- 哪些动作已经恢复、哪些仍可恢复、哪些因外部变化不能安全恢复。

任务历史必须持久化，不能只放在 Renderer 状态或内存中的整理会话里。软件重启后，用户仍然要能打开任务、查看操作明细并继续处理可回滚项。

任务记录分为三层：

```text
整理上下文
  -> 原始快照、规则版本、预览版本、用户选择
操作账本
  -> 每个逻辑文件系统动作的前后状态、规则来源、依赖和恢复条件
执行事件
  -> 实际执行/回滚的每一步开始、成功、跳过、失败和错误
```

其中“操作账本”是回滚的依据，“执行事件”是排障和断点恢复的依据。不能只记录最终路径，也不能只记录一条任务汇总消息。

## 4. 功能边界

### 4.1 第一版必须支持

1. 选择整理根目录并读取目录快照。
2. 按文件、文件夹或两者筛选整理对象。
3. 按扩展名、名称、类型、路径、层级和目录结构匹配。
4. 判断纯数字目录、UUID 目录和用户指定的无意义目录。
5. 创建文件夹。
6. 重命名文件夹。
7. 移动文件和文件夹。
8. 按目标名称合并同级目录。
9. 可选地修改文件名。
10. 支持多规则组和规则组顺序。
11. 支持目录规则影响子项最终路径。
12. 预览原始树与目标树的差异。
13. 预览表格逐项勾选执行。
14. 显示规则命中链和动作解释。
15. 检查文件冲突、目录冲突和循环移动。
16. 执行前校验目录是否发生变化。
17. 复用任务日志和回滚机制。
18. 整理执行前创建持久化任务，并关联快照、预览和规则配置快照。
19. 每个实际成功的动作立即写入操作账本，不能等任务结束后批量补写。
20. 任务详情展示执行动作、命中规则、前后路径、执行状态和回滚状态。
21. 回滚前校验节点身份、路径占用和文件指纹；不满足条件的项目必须暂停并说明原因。
22. 回滚单独生成关联任务，保留原整理任务和原始执行记录。

### 4.2 第一版明确不支持

- 图片内容分类，例如识别人物、风景或截图主题。
- 视频内容分类，例如识别电影名称或课程名称。
- OCR 提取文件内容作为自动命名依据。
- 根据压缩包内部内容自动决定外部目录名称。
- 无用户确认的语义目录合并。
- 无用户确认的文件内容去重删除。
- 任意 DAG 规则依赖编辑器。
- 让用户直接编写脚本改变文件系统。
- 以“智能推荐”代替用户可检查的规则和预览。
- 没有操作账本时仅凭 `from/to` 交换执行“强制回滚”。
- 覆盖用户后续新建或修改内容的无条件恢复。

## 5. 用户流程

整理页位于“规则”旁边，整体工作流与改名、重复模块保持一致：

```text
1 选择文件夹
2 加载目录并使用输入助手筛选
3 设置规则和预览
4 确认执行
```

每一步都有明确目标和边界。

### 5.1 第一步：选择文件夹

#### 目标

确定本次整理的根目录，建立一次稳定的原始快照，作为后续所有规则计算的输入。

#### 页面内容

- 目录路径输入框
- 系统目录选择按钮
- 当前是否已加入资料库的提示
- 目录加载状态和错误信息

第一步只负责确定整理根目录。选择成功后自动进入第二步并加载目录内容，不在第一步配置规则，也不执行任何文件操作。

读取成功后显示：

```text
整理根目录：D:\资料\下载
直属文件：128
直属文件夹：16
后代文件：2,480
后代文件夹：230
最大层级：5
```

#### 读取范围

默认读取整理根目录及其所有后代对象，但支持选择：

- 只读取当前目录直属对象
- 读取全部后代
- 最大深度
- 是否包含隐藏对象
- 是否包含系统对象

#### 边界

1. 第一步只建立快照，不移动、不改名、不创建目录。
2. 不能把未读取的目录当成空目录。
3. 读取失败的对象必须标记为不可确定，不能静默从整理结果中消失。
4. 快照必须保存节点 ID、父子关系、原始路径和必要的校验信息。
5. 后续页面展示的“原始位置”必须来自该快照，而不是来自规则执行后的磁盘。

### 5.2 第二步：加载目录并设置筛选范围

#### 目标

确定哪些对象参与本次整理。筛选范围不产生移动或改名动作，只决定输入集合。

#### 简单入口

```text
整理对象：
( ) 当前目录内的文件
( ) 当前目录内的文件和文件夹
( ) 所有子目录中的文件
( ) 所有子目录中的文件和文件夹
```

快捷筛选：

- 全部文件
- 图片文件
- 视频文件
- 文档文件
- 文件夹
- 无意义名称文件夹
- 空文件夹

#### 高级入口

使用与搜索、改名规则组统一的输入助手和条件组：

```text
文件夹名称 是纯数字
并且
子文件数量 大于 0
并且
包含扩展名 pdf
```

可用条件分为四类：

1. 当前对象：名称、扩展名、类型、路径、层级、大小、时间。
2. 父目录：父目录名称、父目录路径、父目录层级、父目录属性。
3. 子项结构：子项数量、文件数量、目录数量、包含扩展名、主要扩展名。
4. 用户条件：关键词、正则、固定目录列表、目录别名组。

#### 边界

1. 筛选条件不能改变节点的名称和路径。
2. “筛选到文件夹”不等于“整理文件夹内所有文件”；二者必须在界面上分开选择。
3. 过滤条件为空时，要明确显示是“全部对象”还是“默认只处理文件”，不能靠文案猜测。
4. 不能用内容识别结果作为默认筛选条件。
5. 筛选结果必须提供数量预览，避免用户在规则页才发现范围过大或为空。

### 5.3 第三步：设置规则和预览

#### 目标

将筛选范围内的原始目录树转换成目标目录树，并生成可解释的整理计划。

第三步是整理模块的核心页面。主页面不直接铺开全部规则编辑内容，只提供“设置规则”入口和整理预览；点击入口后打开规则列表弹窗，新增、查看和设置单条规则都在弹窗内完成。至少包含：

```text
“设置规则”入口
规则列表弹窗
单条规则设置弹窗
全局整理设置
预览统计
变更列表
原始树 / 目标树对比
命中详情
```

#### 第三步的边界

1. 仍然只计算虚拟结果，不修改真实文件系统。
2. 规则可以创建虚拟目录，但必须在预览中列出创建动作。
3. 规则可以计算最终文件夹名和文件名，但不能直接执行重命名。
4. 规则冲突必须在本步骤暴露，不能推迟到执行时才发现。
5. 预览中没有最终路径的对象，不允许进入可执行状态。

### 5.4 第四步：选择执行项并执行

#### 目标

让用户确认最终操作范围，执行已经生成的计划，并保留回滚记录。

第四步提供：

- 全选、全不选
- 只选无风险项目
- 只选目录项目
- 只选文件项目
- 跳过冲突项目
- 目标位置选择
- 移动或复制选择（第一版可先只支持移动）
- 是否删除整理后为空的目录
- 执行按钮
- 执行前校验结果

#### 默认执行策略

```text
方式：移动
目标：当前整理根目录内
冲突：不覆盖，冲突项目暂停
空目录：不删除
保留回滚：开启
```

#### 边界

1. 执行前只校验计划，不重新猜测规则并覆盖用户选择。
2. 原始对象不存在、属性发生重大变化或目标出现新冲突时，应暂停受影响项目。
3. 执行顺序必须由核心执行器计算，前端不能直接按表格行顺序调用文件 API。
4. 父目录和子项操作必须去重，不能因为父目录移动而再次移动子文件。
5. 执行完成后必须记录原路径、目标路径、规则来源和任务 ID。
6. 执行开始前先创建整理任务；任务创建成功后才允许进行第一个真实 IO。
7. 每完成一个真实 IO，就立即持久化该操作的结果和可回滚信息；进程中断时，已完成部分不能丢失。
8. 执行结果必须区分“任务整体状态”和“单项操作状态”，不能因为存在失败项就隐藏已经成功的操作。
9. 回滚只允许作用于本整理任务实际成功的操作，并且必须生成独立的回滚任务。

## 6. 整理步骤内的规则设计

整理规则是当前整理会话的独立草稿，不读取、不修改全局“规则”页面的规则集。顶栏搜索和 Spotlight 也不是同一控件，不与魔法棒合并；魔法棒统一的是输入助手函数、插入方式和帮助说明。

### 6.1 规则列表弹窗

规则列表参考重复和改名模块的列表设计，但整理规则显示的信息更完整：

```text
规则组 1：数字资料目录
对象：文件夹
条件：名称为纯数字，并且包含文件
动作：根据指定 PDF 文件名重命名
子项：继续按文件类型整理
命中：38 项
风险：2 项待确认
```

每条规则提供：

- 启用/禁用
- 上移/下移
- 新增
- 复制
- 查看
- 设置
- 删除
- 查看本组预览

规则列表顺序表示本次整理的优先级，不显示可编辑的数字 priority。上下移动规则就是调整优先级；规则仍然只在虚拟目录中计算，不表示真实文件系统立即执行。

### 6.2 单条规则设置弹窗

单条规则使用“当什么条件成立，依次执行哪些动作”的结构，普通用户不需要接触 JSON：

1. 规则名称与启用状态，名称和启用控件在同一行对齐。
2. 处理对象：文件、文件夹或两者。
3. 处理范围：当前文件夹直属对象、所有子文件夹对象、当前文件夹及所有子文件夹。
4. 条件：使用输入助手；留空表示该对象范围内的全部对象。空格分隔关键词默认 OR，显式插入“并且”才表示 AND。
5. 动作链：一条规则可以有多个动作，按列表顺序执行；每个动作都可设置、上移、下移或删除。
6. 模板：移动使用目标路径模板，改名使用名称模板；模板输入助手每个函数旁提供问号图标，悬浮显示用法和效果示例。

高级条件 JSON 和原因说明暂不作为普通用户入口。内部仍可兼容旧规则数据，但不让普通用户先理解实现细节。

### 6.3 动作链语义

动作链只对当前规则命中的对象执行，核心执行顺序如下：

```text
动作 1 -> 更新虚拟路径
动作 2 -> 读取动作 1 后的虚拟名称、父目录和路径
动作 3 -> 继续读取最新虚拟状态
```

例如：先将 `lesson.txt` 改名为 `课程.txt`，再移动到 `归档/{name}{ext}`，目标必须是 `归档/课程.txt`。父目录改名或移动后，虚拟目录树会同步更新全部后代路径，后续动作不重新扫描真实磁盘，也不会重复移动子项。

以下内容是高级能力的设计边界，按 P1/P2 逐步补齐。

#### 区域 A：规则组名称

```text
规则组名称：处理数字资料目录
说明：可选，用于预览解释
```

名称用于人理解和预览，不参与匹配。

#### 区域 B：匹配对象

```text
匹配对象：
( ) 文件
( ) 文件夹
( ) 文件夹中的直属文件
( ) 文件夹中的全部后代文件
( ) 文件夹及其全部后代对象
```

这一区分“匹配当前文件夹”和“匹配文件夹里的文件”，是处理嵌套结构的基础。

#### 区域 C：匹配条件

默认显示可视化条件行：

```text
名称       是纯数字
并且
子文件数量 大于 0
并且
包含扩展名 pdf
```

条件行支持：

- 添加条件
- 删除条件
- AND / OR
- 条件组嵌套
- 切换简单条件和高级输入助手
- 查看当前条件生成的语法
- 查看命中数量

高级条件必须区分状态来源：

```text
字段来源：
( ) 原始结构
( ) 当前阶段虚拟结构
( ) 当前对象最终计算值
```

默认选择“当前阶段开始前的结构”。界面不能只显示“名称”，还要在高级提示中显示它实际匹配的是原始名称还是虚拟名称。

#### 区域 D：处理动作

动作按固定槽位配置，不允许用户任意打乱执行顺序。

```text
当前对象名称：保持原名 / 重命名
当前对象位置：保持位置 / 移动 / 合并
子项处理：不处理 / 继续处理 / 扁平化
子项名称：保持原名 / 使用模板
```

动作槽位规则：

1. 当前对象名称最多一个最终结果。
2. 当前对象位置最多一个最终结果。
3. 子项位置可以由子规则独立计算，但必须继承父目录最终路径。
4. 文件名最多一个最终模板，多个改名规则必须显式选择组合顺序。
5. 冲突处理由全局设置提供，也可以在规则组中覆盖，但必须在预览中显示。

### 6.3 目录重命名配置

目录重命名必须明确名称来源：

```text
新名称来源：
( ) 固定名称
( ) 当前目录中第一个指定扩展名文件名
( ) 文件名包含关键词的候选项
( ) 多个文件名的公共前缀
( ) 用户从候选列表中选择
( ) 名称模板
```

如果使用文件名作为目录名，必须配置：

- 候选扩展名
- 是否去掉扩展名
- 是否清理副本后缀
- 是否使用第一个、最长、最短或用户选择的候选
- 多个候选时是否暂停

默认行为：多个候选时暂停，不静默取第一个。

示例：

```text
目录：123456
候选：课程介绍.pdf、课程说明.pdf
结果：需要确认
```

### 6.4 目标目录策略

目标目录必须是一个明确的策略，而不是隐藏的全局猜测：

```text
目标目录：
( ) 当前对象所在目录
( ) 当前目录下已有的同名目录
( ) 整理根目录下已有的同名目录
( ) 固定目标目录
( ) 目标目录模板
```

推荐默认策略：

```text
优先使用当前逻辑目录下已有目标目录，找不到时创建。
```

“最近目录”必须明确搜索范围：

- 只查当前目录
- 允许向上查找
- 最多向上 N 层
- 不得超出整理根目录

默认不跨出整理根目录，也不默认跨父级寻找。

### 6.5 子项处理策略

目录规则需要明确对内部项目的影响：

```text
子项处理：
( ) 不处理子项
( ) 子项继续匹配后续规则
( ) 子项只匹配指定规则组
( ) 扁平化一层
( ) 扁平化全部后代
```

目录改名或移动后，子项最终路径自动继承父目录的虚拟结果。

不能让用户手工为每个子项拼接父路径。

## 7. 规则阶段和 A/B 规则问题

### 7.1 为什么不能按真实执行顺序匹配

假设原始结构：

```text
123456/
├─ 课程介绍.pdf
└─ 1.mp4
```

规则 A：

```text
目录名为纯数字 -> 重命名为课程介绍
```

规则 B：

```text
父目录名为 123456 -> mp4 移动到视频
```

如果 A 立即修改磁盘，B 读取到的是“课程介绍”，自然无法命中。

整理模块必须采用原始快照和虚拟树：

```text
原始快照 S0
  -> 计算 A，得到虚拟状态 V1
  -> 计算 B，得到虚拟状态 V2
  -> 合并最终计划
```

B 可以选择匹配原始状态，也可以在后续阶段匹配 V1，但两者都不能依赖真实磁盘的中间状态。

### 7.2 默认阶段

为了保持简单，第一版固定三个阶段：

#### 阶段一：目录识别和规范化

- 识别数字目录、UUID 目录和用户指定目录
- 重命名目录
- 合并同名或用户映射目录
- 创建基础目录

#### 阶段二：对象归类

- 移动文件
- 移动文件夹
- 按扩展名、名称和结构归类
- 扁平化或保留层级

#### 阶段三：名称处理

- 修改文件名
- 修改文件夹名
- 添加序号
- 使用改名模板

阶段顺序由系统固定，用户可以启用或禁用每个阶段，但不用配置任意规则依赖。

### 7.3 规则组匹配状态

默认规则组使用“阶段开始时的虚拟结构”匹配。规则组计算产生的变化进入下一阶段的虚拟结构。

例如：

```text
阶段一：目录 123456 -> 课程介绍
阶段二：在课程介绍这个虚拟目录下处理 mp4
阶段三：对最终文件名应用用户选择的模板
```

高级设置可查看：

```text
匹配状态：原始快照 / 当前阶段虚拟状态 / 最终状态
```

第一版不提供任意规则组之间的循环依赖和自由 DAG 配置，避免用户需要理解流程编程。

### 7.4 节点 ID 和路径继承

每个节点必须有稳定 ID：

```text
folder-001
file-001
```

目录改名或移动不会改变节点 ID。规则命中依据可以是名称和路径，但动作合并依据必须是节点 ID。

最终路径由虚拟父子关系推导：

```text
最终路径 = 虚拟父目录最终路径 + 虚拟节点最终名称
```

如果父目录整体移动，子项不生成重复的独立移动动作；只有子项有独立归类目标时，才生成新的虚拟父目录关系。

### 8.1 预览是第 3 步的主区域

页面建议采用上下或左右联动布局：

```text
上方：规则组和全局设置
中间：统计与筛选工具栏
下方：变更列表 + 树对比 + 命中详情
```

窗口较小时，规则区和预览区使用独立滚动容器，不能让规则卡片遮挡预览底部。

预览顶部显示：

统计必须随着规则编辑实时更新或在用户点击“刷新预览”后更新，并明确显示计算状态。

快捷过滤：

- 全部
- 仅变化
- 仅文件夹
- 仅文件
- 仅创建目录
- 仅重命名
- 仅移动
- 仅合并
- 仅风险项

### 8.3 变更列表

变更列表至少包含：

| 选择 | 类型 | 整理前 | 整理后 | 动作 | 命中规则 | 风险 |
| --- | --- | --- | --- | --- | --- | --- |
| 已选 | 文件夹 | `123456` | `课程介绍` | 重命名 | 阶段一：数字资料目录 | 无 |
| 已选 | 文件 | `123456/1.mp4` | `课程介绍/视频/1.mp4` | 移动 | 阶段二：视频归类 | 创建目录 |
| 已选 | 文件 | `123456/课程介绍.pdf` | `课程介绍/文档/课程介绍.pdf` | 移动 | 阶段二：文档归类 | 无 |
| 未选 | 文件 | `image/a.jpg` | `图片/a.jpg` | 移动并合并 | 阶段一：目录映射 | 同名冲突 |

显示原则：

- 整理前位置或名称使用红色。
- 整理后位置或名称使用绿色。
- 未变化内容使用灰色。
- 风险使用橙色或红色。
- 被用户取消的项目保留在列表中，但显示为跳过。
- 路径过长时截断，悬停显示完整路径。
- 每行必须可以展开详情。

### 8.4 原始树和目标树对比

提供目录树对比视图：

```text
整理前                         整理后
下载/                           下载/
└─ 123456/                      └─ 课程介绍/
   ├─ 课程介绍.pdf                 ├─ 文档/
   └─ 1.mp4                       │  └─ 课程介绍.pdf
                                  └─ 视频/
                                     └─ 1.mp4
```

树对比必须标识：

- 新建目录
- 删除或变空目录
- 改名目录
- 移动节点
- 保持不变节点
- 冲突节点

选择树节点时，变更列表和命中详情同步定位到相同节点 ID。

### 8.5 命中规则详情

用户点击一行后，显示完整的解释链：

```text
对象：123456/1.mp4

命中过程：
1. 阶段一的“数字资料目录”命中父目录 123456。
2. 父目录虚拟名称计算为“课程介绍”。
3. 阶段二的“视频归类”命中扩展名 mp4。
4. 当前虚拟目录下没有“视频”目录。
5. 计划创建“课程介绍/视频”。
6. 文件名保持原名。

最终结果：课程介绍/视频/1.mp4
```

每个命中记录应保存：

- 规则组 ID 和名称
- 所属阶段
- 匹配状态来源
- 匹配时的虚拟路径
- 匹配条件结果
- 产生的动作
- 动作产生的目标
- 被其他动作继承的父路径变化
- 风险和阻断原因

### 8.6 选择和依赖

预览项默认全选，但存在以下依赖：

```text
目录改名 -> 子项最终路径变化
目录移动 -> 子项路径继承
创建目录 -> 文件移动的前置依赖
目录合并 -> 子项冲突处理
移动文件 -> 空目录删除判断
```

如果用户取消父目录动作，系统必须立即重新计算受影响的子项，并提示：

```text
父目录改名已取消，3 个子项的目标路径将随之变化。
```

不能保留一套旧的子项目标路径而不提醒用户。

## 9. 冲突、异常和安全边界

### 9.1 文件冲突

目标路径已存在文件时，提供：

- 跳过
- 保留目标文件
- 保留源文件并自动编号
- 内容相同则跳过源文件
- 移动到冲突目录

默认不覆盖。

内容相同的判断只能基于文件大小相同后的哈希比较。文件名相同或不同都不能单独证明内容重复。

### 9.2 目录冲突

目标目录已经存在时：

1. 可以把源目录子项合并到目标目录。
2. 子项冲突必须逐项生成风险。
3. 源目录为空后才可标记为“可删除”。
4. 删除空目录必须独立勾选，默认关闭。

### 9.3 循环和非法路径

执行前必须阻断：

- 将目录移动到自身
- 将目录移动到自身子目录
- 目标路径和源路径相同但动作被误判为移动
- Windows 保留名称
- 非法字符
- 路径长度超限
- 大小写变化导致的同路径冲突
- 跨磁盘移动无法原子完成

### 9.4 预览后文件系统变化

执行前校验：

- 节点是否仍存在
- 原始路径是否仍指向相同节点
- 文件大小是否变化
- 修改时间是否变化
- 目标是否出现新文件或目录

不重新运行规则覆盖用户选择。变化项目标记为“预览已过期”，用户可以：

- 重新生成预览
- 仅执行未受影响项目
- 取消执行

```ts
    executed: number
    skipped: number
    failed: number
    rollbackable: number
  }
}
```

要求：

1. `ruleSetVersion` 使用规则集内容的稳定版本号或内容哈希，不能使用会被覆盖的“当前版本”。
2. `ruleSetSnapshot` 保存执行时实际使用的规则组、条件、动作、顺序和说明；体积较大时可以单独存表，但必须由任务 ID 可追溯查询。
3. `selectedOperationIds` 记录用户在第四步最终确认的逻辑操作，而不是只记录数组下标。预览重新排序后，操作身份不能漂移。
4. `snapshotId` 和 `previewId` 必须能定位原始目录快照和用户看到的那一版预览，执行前的过期校验也使用它们。
5. 任务摘要是缓存，不是事实来源；实际统计以操作账本和执行事件重新聚合为准。

### 10.7 整理操作账本

现有通用 `job_ops` 可以承载基础 `from/to/op/status`，但整理任务需要扩展字段，或增加一张由 `job_id` 关联的 `organize_job_ops` 明细表。推荐第一版采用通用表加 `metadata_json`，当查询和筛选需求稳定后再拆专用表。

```ts
type OrganizeJobOpRecord = {
  jobId: string
  seq: number
  opId: string
  nodeId: string
  kind: 'file' | 'directory'
  operation: 'mkdir' | 'rename' | 'move' | 'merge' | 'delete' | 'flatten'
  fromPath: string | null
  toPath: string | null
  fromName: string | null
  toName: string | null
  sourceRuleIds: string[]
  stage: 'directory-normalize' | 'classify' | 'name'
  parentNodeId: string | null
  dependencyOpIds: string[]
  status: 'planned' | 'running' | 'ok' | 'skipped' | 'failed' | 'rolled-back' | 'rollback-failed'
  risk: string
  reason: string
  error: string | null
  beforeFingerprint: string | null
  afterFingerprint: string | null
  executedAt: number | null
  rolledBackAt: number | null
  rollbackReason: string | null
}
```

至少必须持久化以下信息：

| 信息 | 用途 |
| --- | --- |
| `opId`、`nodeId`、对象类型 | 稳定关联预览项和真实节点，避免仅依赖路径或行号 |
| 原始/目标路径和名称 | 展示“从哪里到哪里”，并生成逆向动作 |
| 规则 ID 列表、阶段、解释 | 回答“为什么这样整理”，兼容多条规则共同命中 |
| 依赖操作 | 先恢复子项再恢复父项，处理目录合并和创建目录 |
| 执行前/后指纹 | 判断目标是否仍是本任务产生的结果，避免误伤后续新文件 |
| 操作状态、错误、时间 | 支持部分失败、重启后排障和任务统计 |
| 回滚状态和原因 | 明确已恢复、待恢复、跳过或无法安全恢复 |

### 10.8 执行事件日志

操作账本记录“这个动作是什么”，事件日志记录“这个动作实际发生了什么”。每个操作至少产生以下事件：

```ts
type OrganizeJobEvent = {
  jobId: string
  opId: string | null
  phase: 'execute' | 'rollback'
  event: 'started' | 'ok' | 'skipped' | 'failed' | 'verification-failed'
  path: string | null
  message: string | null
  at: number
}
```

跨盘移动不能只记作一个模糊的 `move`。如果实际过程是“复制 -> 校验 -> 删除源文件”，事件日志必须至少能区分复制成功、校验成功和源文件删除成功；否则回滚无法判断当前磁盘上到底有几份有效数据。

### 10.9 回滚状态模型

任务与单个操作分别维护状态。任务级状态建议为：

| 状态 | 含义 |
| --- | --- |
| `running` | 正在执行真实整理动作 |
| `completed` | 所有用户选中且可执行操作完成 |
| `partial` | 有成功、跳过或失败混合结果，仍可能存在可回滚项 |
| `failed` | 任务无法继续或所有有效操作均未完成 |
| `cancelled` | 用户取消，已完成项仍保留在账本中 |
| `rolled_back` | 本任务所有可安全恢复项均已恢复 |
| `rollback_partial` | 回滚任务完成，但仍有跳过或失败项 |

单项回滚状态建议为：

```text
not-applicable -> rollbackable -> rolling-back -> rolled-back
                                      \-> rollback-skipped
                                      \-> rollback-failed
```

“已回滚”不能通过删除原 `job_ops` 记录表示，必须保留原操作并更新回滚状态，同时在新的 `organize-rollback` 任务中记录实际逆向操作。

## 11. 规则计算与执行顺序

### 11.1 计算顺序

```text
1. 读取并冻结原始快照
2. 建立虚拟树 V0
3. 应用阶段一规则，得到 V1
4. 应用阶段二规则，得到 V2
5. 应用阶段三规则，得到 V3
6. 推导所有节点最终路径
7. 合并父子动作，消除重复移动
8. 生成创建目录、移动、重命名、合并和删除动作
9. 检查冲突、循环和非法路径
10. 生成预览和解释链
```

### 11.2 真实执行顺序

真实执行由核心执行器根据依赖生成，推荐顺序：

```text
1. 创建临时目录或目标目录
2. 为解决路径占用生成临时名称
3. 执行必要的目录重命名和目录移动
4. 执行文件移动
5. 执行文件和目录最终改名
6. 合并完成后处理空目录
7. 写入任务日志和回滚数据
```

执行器必须支持临时名称，避免以下情况失败：

```text
A -> B
B -> A
```

### 11.3 父子动作去重

如果父目录整体移动：

```text
移动目录 123456 -> 课程介绍
```

其子文件不再生成从旧路径到新父路径的重复移动。

如果某个子文件有独立归类：

```text
123456/1.mp4 -> 课程介绍/视频/1.mp4
```

则只保留最终虚拟父节点关系，执行器计算实际需要的最少动作。

### 11.4 执行任务创建与写入时机

执行采用“先建任务，再逐项提交账本”的方式：

```text
校验预览版本和快照
  -> 创建 organize-execute 任务（running）
  -> 写入任务上下文和选中操作
  -> 对每个操作：写入 running 事件
  -> 执行一个真实 IO
  -> 校验结果和目标状态
  -> 立即写入 job_ops / 操作账本和 ok、skipped 或 failed 事件
  -> 更新任务统计和当前进度
  -> 任务结束时汇总最终状态
```

必须遵守以下原子性边界：

1. 任务创建、任务上下文写入和第一项真实 IO 之间不能出现“无任务执行”。
2. 一个操作的账本记录必须在真实 IO 前进入 `running`，在 IO 和结果校验完成后进入终态。
3. 真实 IO 成功但进程在写入终态前崩溃时，启动恢复程序必须把该项标记为“需要复核”，不能直接假定失败或再次执行。
4. 任务汇总统计可以重算，不能用汇总统计替代逐项事实记录。
5. 执行器按依赖图排序；前端表格的显示顺序和用户勾选顺序不决定真实执行顺序。
6. 父目录整体移动后，不再对其子项重复执行等价移动；但子项有独立目标时，必须保留其相对父目录的后续动作。

### 11.5 回滚算法

点击任务页的“回滚”后，系统先生成一个与原整理任务关联的 `organize-rollback` 任务，再进行安全检查和逆向执行：

```text
读取原整理任务的成功操作
  -> 依据依赖关系生成逆序恢复计划
  -> 对每项检查当前路径、目标占用和 afterFingerprint
  -> 创建 rollback 任务
  -> 先恢复子文件/子目录
  -> 再恢复父目录和目录名称
  -> 删除本任务创建且仍为空的目录
  -> 记录每一步恢复结果
  -> 更新原任务每项的 rollback 状态
```

具体语义：

| 原操作 | 回滚动作 | 安全条件 |
| --- | --- | --- |
| `rename` / 同卷 `move` | `to -> from` | `to` 仍存在、`from` 未被其他内容占用，且节点/指纹匹配 |
| `mkdir` | 删除创建的目录 | 目录仍存在、为空、创建时间和任务归属匹配；有用户新增内容则跳过 |
| `merge` | 先恢复被移动的子项，再恢复源目录 | 所有子项均可恢复；存在冲突时暂停，不直接覆盖 |
| `flatten` | 恢复原父目录层级 | 原目录没有被用户重新利用，且恢复不会覆盖现有项目 |
| 跨盘 `move` | 按记录恢复源位置并处理目标副本 | 必须依据 copy/verify/delete 事件决定是否保留或清理副本 |
| `delete` / 隔离 | 从隔离区恢复到原路径 | 原路径可用、隔离对象未被替换；恢复冲突须人工选择 |

回滚不是简单地把 `from_path` 和 `to_path` 交换：

1. `mkdir` 的逆操作是“有条件删除”，不能把用户后来放入的文件一起删除。
2. 父目录操作必须在子项恢复后执行，否则恢复路径可能不存在或子项被再次搬动。
3. 合并操作必须保留源目录、目标目录和每个子项的原始父节点信息。
4. 跨盘移动必须根据真实事件判断源文件是否已删除、目标文件是否校验通过，不能只看最终 `ok`。
5. 回滚发现路径或指纹不一致时，将该项标为 `rollback-skipped` 或 `rollback-failed`，并暂停依赖它的后续项。
6. 回滚完成后刷新索引；刷新失败不掩盖文件系统恢复结果，需在任务中单独记录。

### 11.6 中断恢复与重复点击保护

应用启动时扫描处于 `running`、`rollback-running` 或存在 `running` 操作账本的任务：

- 先读取事件日志和当前文件系统状态；
- 对已完成且可证明成功的动作补写终态；
- 对无法证明的动作标记为“需要复核”；
- 不自动重复执行可能已经成功的危险动作；
- 任务页提供“重新预览剩余项”“继续执行可确认项”“回滚已确认成功项”三个明确入口。

回滚按钮需要幂等保护：

1. 完整回滚后按钮变为不可用，显示已回滚时间。
2. 部分回滚后只对剩余 `rollbackable` 项提供操作，并显示剩余数量。
3. 同一任务已有回滚任务运行时，禁止再次创建回滚任务。
4. 原整理任务永不删除、不覆盖，回滚任务通过 `parentJobId` 关联。

### 11.7 任务页设计

任务页的整理任务详情采用“汇总 + 操作账本 + 事件时间线”三层结构。

任务头部：

```text
整理任务
状态：部分完成 / 可回滚
根目录：D:\下载
规则版本：规则组-20260912-abc123
预览版本：preview-...
开始时间：...
完成时间：...
操作：已选 120，成功 116，跳过 2，失败 2，可回滚 116
[查看预览] [查看操作明细] [回滚]
```

操作明细表：

| 序号 | 对象 | 原位置 | 执行后位置 | 动作 | 命中规则 | 执行状态 | 回滚状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 12 | `1.mp4` | `下载/123/1.mp4` | `下载/课程/视频/1.mp4` | 移动 | 数字目录改名、视频归类 | 成功 | 待回滚 |
| 13 | `课程` | `下载/123` | `下载/课程` | 改名 | 目录名来自课程介绍.pdf | 成功 | 待回滚 |
| 14 | `a.jpg` | `下载/123/a.jpg` | `下载/课程/图片/a.jpg` | 移动 | 图片归类 | 跳过 | 不可回滚 |

展开某一行必须能看到：

```text
对象：文件 / 目录，nodeId：...
原始状态：名称、路径、大小、修改时间、beforeFingerprint
执行动作：动作类型、来源规则、阶段、依赖操作
执行后状态：名称、路径、大小、修改时间、afterFingerprint
执行事件：开始、成功/跳过/失败、错误信息
回滚动作：目标路径 -> 原路径
回滚检查：通过 / 被外部修改 / 目标被占用
回滚结果：待回滚 / 已恢复 / 已跳过 / 失败
```

任务页筛选至少支持：

- 仅目录、仅文件；
- 仅移动、仅改名、仅创建、仅合并、仅隔离；
- 仅成功、仅跳过、仅失败；
- 仅可回滚、仅已回滚、仅回滚失败；
- 按规则组、阶段、风险和路径过滤。

任务详情中的“查看预览”必须打开执行前用户看到的那一版预览，而不是根据当前规则重新计算。这样任务历史才能和实际执行结果一一对应。

## 12. 十个复杂嵌套案例

以下案例使用同一套“条件 -> 规则组 -> 阶段 -> 预览 -> 执行”模型。案例从简单归类逐步增加目录识别、改名、合并、父子关系、冲突和多阶段处理。

| # | 原始结构和条件 | 规则设计 | 目标结果和产品目标 |
| --- | --- | --- | --- |
| 1 | `下载/` 下有 `a.jpg`、`b.png`、`c.mp4`；只处理直属文件。 | 阶段二新增“图片”规则：对象为文件，扩展名为 `jpg,png`，移动到当前目录下的 `图片`，文件名保持原名。新增“视频”规则：扩展名为 `mp4`，移动到 `视频`。目标策略为当前目录已有则复用，没有则创建。 | `下载/图片/a.jpg`、`下载/图片/b.png`、`下载/视频/c.mp4`。验证最简单的文件归类、目录创建和原名保留。 |
| 2 | `资料/项目甲/原始/a.pdf`、`资料/项目甲/原始/b.docx`；文档已经在有意义目录内，不希望扁平化。 | 处理对象为文件；条件为扩展名属于文档；目标为“当前逻辑目录下的文档”且保留当前父目录；不处理父目录改名。 | `资料/项目甲/原始/文档/a.pdf`、`资料/项目甲/原始/文档/b.docx`。验证目标目录使用当前最近目录，而不是移动到根目录的全局文档目录。 |
| 3 | `下载/123456/课程介绍.pdf`、`下载/123456/1.mp4`、`下载/123456/封面.jpg`；数字目录名称无意义，但文件名正常。 | 阶段一规则：对象为文件夹；条件为目录名是纯数字且文件数量大于 0；目录名来源选择“指定扩展名 pdf 文件名”，多个候选时暂停。阶段二对子项继续处理：`mp4 -> 视频`、`jpg -> 图片`，pdf 保留或移入文档。 | `下载/课程介绍/课程介绍.pdf`、`下载/课程介绍/视频/1.mp4`、`下载/课程介绍/图片/封面.jpg`。验证目录改名、子项归类和父路径继承同时成立。 |
| 4 | `下载/98765/说明.txt`、`下载/98765/课程说明.pdf`、`下载/98765/1.mp4`；没有唯一的命名候选。 | 阶段一条件仍为纯数字目录；目录命名来源为“文件名包含课程的 pdf”；如果没有唯一命中则规则状态为需要确认，不生成确定的目录改名动作。阶段二仍可对 mp4 生成相对父目录的归类预览。 | 预览显示目录改名为“需要选择候选”，mp4 可显示 `98765/视频/1.mp4` 或依赖于用户选择后更新。目标是避免系统把 `说明.txt` 或错误文件名静默作为目录名称。 |
| 5 | `课程/视频/1.mp4`、`课程/图片/1.jpg`；文件名是数字，但父目录名称正常。 | 规则只作用于文件夹或文件位置，不启用文件名修改。视频和图片规则的目标策略为“当前目录已有同名分类目录则保持”，文件名策略明确为保持原名。 | 结构保持为 `课程/视频/1.mp4`、`课程/图片/1.jpg`，预览标记为保持不变。目标是证明数字文件名不能自动触发错误改名。 |
| 6 | `资料/image/a.jpg`、`资料/images/b.jpg`、`资料/图片/c.jpg`；用户希望统一为“图片”。 | 阶段一建立目录名称映射组：`image, images, 图片 -> 图片`；匹配范围限定为同一父目录；动作是合并目录，不是删除。阶段二处理子项冲突，空源目录单独列为可删除动作。 | `资料/图片/a.jpg`、`资料/图片/b.jpg`、`资料/图片/c.jpg`。目标是支持用户明确控制的目录规范化，不默认把语义相似目录自动合并。 |

| 8 | `课程包/001/课程介绍.pdf`、`课程包/001/视频/1.mp4`、`课程包/002/课程介绍.pdf`、`课程包/002/视频/1.mp4`；两个数字目录改名后会产生同名目录。 | 阶段一：两个数字目录都根据唯一 pdf 候选改为 `课程介绍`。检测到同一父目录下目标名称相同，进入目录合并规则。阶段二合并子项；同名 `视频/1.mp4` 触发文件冲突策略，默认不覆盖并要求选择。 | 预览显示“两个目录合并为课程介绍”，并明确标出 `视频/1.mp4` 冲突。目标是验证目录合并、子项继承和文件冲突不能被静默覆盖。 |

### 12.1 案例共性要求

以上案例必须满足：

1. 任何目录改名都不能让子文件丢失规则关联。
2. 任何文件移动都不能让后续规则依赖真实磁盘重新扫描。
3. 多候选目录名称必须进入待确认状态。
4. 目标目录搜索范围必须在预览解释中出现。
5. 规则冲突必须逐项显示，而不是使用后规则覆盖前规则。
6. 用户取消父目录动作后，子项目标必须重新计算。
7. 预览中的最终路径必须与执行器最终使用的路径一致。

## 13. 交互和可用性要求

### 13.1 默认配置体验

普通用户完成最常见整理只需要：

1. 选择目录。
2. 点击“按文件类型归类”或新增规则组。
3. 选择图片、视频、文档等扩展名集合。
4. 查看预览。
5. 执行。

不应要求用户先理解虚拟树、节点 ID、阶段状态或规则依赖。

### 13.2 复杂配置体验

复杂用户可以逐步展开：

```text
基础设置
  -> 父目录条件
  -> 子项条件
  -> 目录命名来源
  -> 目标目录搜索范围
  -> 子项继续处理
  -> 文件名模板
  -> 冲突策略
```

每次展开都要有即时命中数量和预览变化，不能配置完十几项后才一次性发现规则没有命中。

### 13.3 黑盒控制要求

以下信息必须可见：

- 当前规则是否启用
- 当前规则匹配什么对象
- 使用哪个状态匹配
- 目标目录搜索到哪一级
- 目录名称从哪个文件产生
- 文件名模板是什么
- 多规则命中时采用什么处理
- 为什么某项被跳过
- 为什么某项有风险

隐藏实现细节可以隐藏，但不能隐藏决策依据。

## 14. 性能要求

1. 规则编辑时优先使用索引数据生成候选预览。
2. 虚拟树计算不能反复对每个节点进行完整磁盘扫描。
3. 目录子项统计应复用索引中的计数和关系。
4. 预览列表支持分页或虚拟滚动。
5. 规则变化时可以增量重算受影响的规则组和节点。
6. 生成完整计划时必须显示进度和可取消状态。
7. 大目录的哈希计算不能作为普通结构整理的默认步骤。
8. 只有冲突策略明确选择“内容相同判断”时，才按需计算哈希。

### 15.1 Core

建议在 `packages/core` 增加整理领域模块：



`organize.preview` 返回完整预览计划和解释链；`organize.execute` 接受用户选择后的计划版本，并再次验证快照指纹。

## 16. 验收标准

### 16.1 产品验收

1. 用户可以从规则旁边进入整理页。
2. 四步流程和改名、重复模块一致。
3. 简单用户可以仅通过扩展名规则完成归类。
4. 复杂用户可以配置父目录、子项和目录命名来源。
5. 预览显示每个变化对象的前后位置。
6. 预览显示命中规则和解释链。
7. 预览支持按类型、动作和风险过滤。
8. 预览支持逐项勾选。
9. 目录树对比可以显示多层嵌套变化。
10. 冲突项目默认阻断或暂停，不静默覆盖。
11. 点击执行后立即生成整理任务，任务详情能打开本次执行使用的预览和规则快照。
12. 任务详情能逐项显示实际操作了什么、命中什么规则、执行结果是什么。
13. 任务详情能显示当前可回滚数量，并区分已回滚、跳过和回滚失败。
14. 点击回滚后生成独立的回滚任务，原整理任务仍保留且能查看回滚关联关系。

### 16.2 核心正确性验收

1. A 规则改名目录后，B 规则仍能根据快照或虚拟阶段命中。
2. 父目录改名后，子文件最终路径自动同步。
3. 父目录整体移动时，子文件不会重复移动。
4. 两个目录合并时，子文件冲突可以逐项处理。
5. 多个候选目录名不会被系统静默选择。
6. 预览路径与实际执行路径一致。
7. 执行前目录变化可以被发现。
8. 执行后可以回滚已完成的动作。
9. 执行中途进程退出后，重启仍能识别已成功、未确认和失败的操作，不重复执行未确认的危险动作。
10. 回滚按依赖逆序执行，先恢复子项，再恢复父目录和创建目录。
11. 用户在目标位置新增文件后，回滚不会覆盖或删除该文件，受影响操作进入跳过/需复核状态。
12. 文件内容或大小在整理后发生变化时，回滚会通过指纹校验阻止无条件覆盖。
13. 目录合并、跨盘移动、隔离恢复均能展示真实子步骤和最终恢复结果。
14. 完整回滚后不能重复创建回滚任务；部分回滚后只显示剩余可安全恢复项。

### 16.3 测试验收

至少覆盖：

- 文件按扩展名归类
- 直属文件和递归文件边界
- 数字目录改名
- UUID 目录识别
- 多候选命名暂停
- 父目录改名和子项移动
- 目录合并和同名文件冲突
- 最近目录搜索边界
- 父目录整体移动去重
- 规则阶段传递
- 执行前快照过期
- Windows 路径、大小写和保留名称

## 18. 最终结论

整理模块采用以下最终模型：

```text
用户配置可读的规则组
  -> 规则按固定阶段作用于虚拟目录树
  -> 节点通过稳定 ID 保持关联
  -> 父目录最终路径自动传递给子项
  -> 所有动作合并为一份可解释 ChangePlan
  -> 预览暴露每个命中、目标和风险
  -> 用户逐项确认
  -> 创建整理任务并冻结执行上下文
  -> 执行器按依赖顺序修改真实文件系统
  -> 每一步写入操作账本和事件日志
  -> 可从原任务生成关联回滚任务，按校验结果逆向恢复
```

最重要的产品承诺是：

> 用户看到的预览，就是执行器将要执行的结果；规则之间不会因为前一个规则尚未真实执行而丢失命中；任何系统无法确定的目录名称、目标路径或冲突，都必须在执行前明确告诉用户。

> 整理任务必须回答“系统实际改了什么”，并保存足够的前后状态、规则来源和恢复条件；回滚不是删除历史或盲目交换路径，而是一个有校验、有结果、有审计记录的逆向任务。
