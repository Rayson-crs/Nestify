# Nestify 六大核心模块与规则流

> 配套文档，对应产品需求 v0.2。页面可按模块切开，底层必须共用索引、规则引擎、变更计划和执行器。
>
> 当前状态（2026-09-17 / v1.8.0）：模块划分仍有效。已落地的是增量扫描、FTS/n-gram 搜索、8 种重复保留策略、模板改名、图片缩略图、整理四步向导。下文部分验收口径仍是 v1 目标，例如视频 ffmpeg 抽帧和 sharp WebP，不能当成当前实现。

## 1. 总评

六块都合理，而且已经足够具体，可以直接指导 M0-M2。不能原样照抄的只有几处安全/性能默认值。

| 模块 | 是否纳入 v1 | 结论 |
| --- | --- | --- |
| 极速增量索引扫描（建巢） | 纳入 | 合理。增量键必须比 mtime+size 更稳，Hash 绝不能首次全量算。 |
| 毫秒级模糊搜索（寻巢） | 纳入 | 合理。搜索字段要再开一层路径/规则命中，不只文件名+扩展名+父目录。 |
| 重复文件分析（清巢） | 纳入 | 合理。禁止一键对全库算完整 Hash；删除走回收站/隔离区双策略。 |
| 细粒度批量重命名（精准雕琢） | 纳入，且是内核皮肤 | 占位符 + 链式清洗非常对，必须补 ancestor(n)、条件表达式和计划层冲突预检测。 |
| 智能缩略图预览（透视眼） | 纳入 | sharp + fluent-ffmpeg 可接受，但视频抽帧和 NAS 必须限流，缓存键不能只用路径。 |
| 一键目录自动归类（筑巢） | 纳入为内置 RuleSet，默认 Dry-Run | 5 条规则方向对，但第 4 条自动搬到盘符 Videos 默认关闭，第 5 条默认隔离不删除。 |
| 规则方案 / Dry-Run / 冲突策略 | 纳入 | 这是全局执行外壳，不单属于重命名页。 |

## 2. 必须修正的不合理点

1. 不要首次全量算 Hash。百万文件、尤其 NAS 上，全量 Hash 会把产品做死。正确顺序：Fast 扫描只记路径/size/mtime/ino；重复分析时先按 size 分桶，再 quick hash，最后 full hash。
2. 增量不能只看 mtime+size。复制覆盖、解压覆盖、部分 SMB/USB 场景下 mtime 不可信。增量键：`path + ino/dev(如有) + size + mtime + is_dir`。变化才重摘信号；Hash 只在重复分析或用户强制 Deep 扫描时补。
3. 删除不能只信系统回收站。`shell.trashItem` 在本地 NTFS 通常可用，网络盘、部分映射盘、无回收站卷会失败或变成永久删除。默认策略：本地优先系统回收站，失败则进 Nestify 隔离区；网络盘/UNC 强制隔离区。严禁静默物理删除。
4. “保留最新”不能作为唯一自动策略，更不能绕过预览。可以做成一键策略，但必须先进 Dry-Run 表。默认保留规则可配：最新 / 最旧 / 路径最短 / 名字信息量最高 / 指定目录优先。v1.8.0 查重页已提供 8 种策略，并增加路径最长、名称最短/最长；确认后只走隔离区，没有执行删除。
5. 模块六第 4 条默认关闭。所有视频自动移入当前盘符 `Videos` 对通用文件管理太武断，会拆散字幕、nfo、同名文件夹和剧集目录。它只能作为可选模板，目标路径必须用户指定，默认建议库内 `Videos/`，不是盘符根。
6. 模块六第 5 条默认隔离，不直接删除。“同名文件夹已存在”不等于已经完整解压且内容一致。没有内容置信度就删压缩包，误删成本太高。
7. 覆盖冲突不要用密码确认。桌面工具做密码确认既烦也假安全。覆盖默认关闭；若用户选择覆盖，需要勾选“我确定覆盖 N 个文件”或输入确认词 `OVERWRITE`，并在计划表里单独标红。
8. `{parent}_{name}_{seq}` 示例要修。原路径 `/电影库/阿凡达/[4K]阿凡达.2009.mp4` 按字面会得到 `阿凡达_阿凡达.2009_1.mp4`，不是 `电影库_阿凡达.2009_1.mp4`。正确示例见模块四。
9. 搜索 300ms 防抖可以，但不是性能来源。快来自索引，不来自防抖。双击定位资源管理器要有，但不能替代应用内预览和规则命中解释。
10. 5 条内置规则不是硬编码引擎。它们必须是可禁用、可改优先级、可编辑的默认 RuleSet，跑在同一套规则 VM 上。

## 3. 模块一：极速增量索引扫描（建巢）

1. 用户添加一个或多个扫描根：盘符、目录、UNC、已映射网络驱动器。
2. 首次：Fast 全量 walk，写入 entries。不计算 full hash，不强制抽媒体帧。
3. 后续启动：对比增量键，无变化复用记录；新增/变更/消失分别 upsert/delete。
4. 扫描与 UI 解耦。底部状态栏常驻：进度条、已扫文件数、目录数、速度、当前路径、错误数、暂停/继续。
5. 扫描中仍可搜索已入库部分。
6. 排除默认开启：`$RECYCLE.BIN`、`System Volume Information`、`.git`、`node_modules`、`__pycache__`、`.nestify-quarantine`。
7. 存储档位：Local SSD 较高枚举并发；HDD 低并发顺序；SMB/NAS 更低并发、更长 timeout、可断点续扫。
8. Hash 策略默认 `duplicate-candidate-only`。用户可在库设置改成 off / on-demand / all。

增量状态机：

```text
seen_unchanged -> reuse row, keep hash/signals
seen_changed   -> update meta, invalidate hash/preview/signals
seen_new       -> insert
missing        -> mark tombstone, 不立刻删历史，便于回滚解释
```

验收：

1. 二次启动对未变化目录几乎只做枚举对比，不再重算 Hash。
2. 状态栏数字与库内实际 entries 对得上。
3. NAS 断连后任务可恢复，不把库标损坏。
4. 取消扫描必须立刻停下 IO，已写入部分可保留。

## 4. 模块二：毫秒级模糊搜索（寻巢）

1. 搜索框即输即搜，防抖默认 300ms，可在设置调整。
2. v1 目标字段是文件名 stem、扩展名、父目录名、完整相对路径、kind/type。v1.8.0 引擎和魔法棒已经超出这份清单，还包括 `size:`、`mtime:`、`ctime:`、`depth:`、`has:`、`missing:`、`child_count:`、`unique_video:` 等。完整目录见 TRD 09。
3. 支持独立或组合：`name:阿凡达 ext:mp4 parent:电影库`，以及 `kind:dir AND unique_video:true`。
4. 空格分词默认 AND；引号包裹短语；`OR` 显式写出。
5. 结果虚拟滚动，列至少包括：缩略图、名称、新名称(若有规则预览)、路径、大小、mtime、类型。
6. 双击：`shell.showItemInFolder` 高亮定位。
7. 单击：应用内预览。
8. Enter 打开文件；`Ctrl+Enter` 定位到资源管理器。
9. 右键：复制路径、加入重命名器、加入重复分析、加入规则测试集。

补强：路径片段搜索必须有；规则命中结果和搜索结果共用同一张表；无结果时给出可执行提示。

验收：

1. 索引完成后，常见文件名查询首屏目标小于 50ms，UI 不得卡死。
2. 300ms 防抖期间以最新关键词为准，不排队打出旧结果。
3. 双击定位在本地盘可用；网络盘失败时给原因，不空失败。

## 5. 模块三：重复文件分析与管理（清巢行动）

1. 入口是“分析重复”，不是“立刻全库 Hash”。
2. 流水线：size 分桶（count>=2 才继续）-> quick hash（头 1MB + size + 尾 64KB）-> full hash 确认。硬链接/同一 inode 标为同一物理文件，不作为浪费空间。
3. 分组展示：浪费空间、路径、mtime、size、名字质量、所在目录是否更规整。
4. 操作策略：保留一个（手动勾选），或 8 种自动保留策略：最新、最旧、路径最短/最长、名称最短/最长、文件名质量、优先目录。策略只决定每组留哪一份，仍进 Dry-Run。
5. 删除执行链：计划 -> 用户确认勾选 -> 隔离区 -> 任务日志 -> 可回滚。查重页已去掉执行删除。
6. 正在占用、权限拒绝、只读，进入失败列表，默认 continue-on-error。

验收：同内容不同名能检出；同名不同内容不会进同一可删组；未点确认前磁盘不变；网络盘删除全部进隔离区。

## 6. 模块四：细粒度批量重命名（精准雕琢）

这是规则引擎面向改名场景的主界面，不是另一套引擎。

### 6.1 过滤器

支持 AND/OR/NOT，字段：

1. 文件名 / stem：等于、包含、前缀、后缀、正则、空、纯数字
2. 扩展名：等于、集合、正则
3. 父目录名、祖父目录名、任意 ancestor(n)、路径包含
4. 文件大小区间
5. 创建/修改时间区间
6. 路径深度
7. kind：file/dir/video/image/archive
8. 子项条件（给文件夹改名用）：子文件数、是否唯一视频、主子文件名

### 6.2 占位符

真相源是 `getContextValue` 和 [packages/core/src/assistant/](../packages/core/src/assistant/)，不是 `PLACEHOLDERS` 那份短列表。完整字段/函数表见 [09-input-assistant-unification-trd.md](./09-input-assistant-unification-trd.md) 第 10、14 节。

| 占位符 | 含义 |
| --- | --- |
| `{name}` / `{stem}` / `{filename}` | 不含扩展名 / 主干 / 完整文件名 |
| `{ext}` / `{ext_no_dot}` | 扩展名，含点或不含点；目录为空 |
| `{parent}` / `{grandparent}` / `{ancestor(n)}` | 向上取目录名；n=1 即 parent，`{ancestor(-1)}` 是上一级 |
| `{drive}` / `{root}` / `{path}` / `{relPath}` | 盘符、库根、绝对/相对路径 |
| `{size}` / `{kind}` / `{is_dir}` / `{depth}` | 大小、类型、是否目录、层级 |
| `{children.*}` / `{children.main_video.*}` | 子项统计、主文件、唯一视频名 |
| `{peer_dir.exists}` | 同名目录在不在 |
| `{seq}` / `{parent_seq}` | 本次计划序号、目录内序号 |
| `{now}` / `{date_created}` / `{date_modified}` | 当前时间、创建、修改。日期格式可改，如 `{date_modified:yyyy-MM-dd}`；不要写 `{mtime:yyyy}` |

### 6.3 链式清洗函数

可作用于任一占位符或中间变量，例如 `{name.trim().regex_replace('\[.*?\]','').trim()}`。

当前 `CHAIN_FUNCS` 已远超早期 v1 那 10 个，助手目录与 `applyChain` 同源。不要再维护一份短列表。常用分组：

- 清理：`.trim()` `.collapse_space()` `.sanitize()` `.remove_ads()` `.remove_bracket_content()` `.collapse_dots()` `.remove_copy_suffix()`
- 抽取：`.extract_year()` `.extract_number()` `.extract_season_episode()` `.extract_resolution()` `.match()`
- 格式：`.pad(n)` `.pad_number(3, '0')` `.prefix()` `.suffix()` `.format_size()`
- 大小写：`.upper()` `.lower()` `.title()` `.snake_case()` 等

函数从左到右。非法正则在预览期报错，不执行。完整表见 TRD 09 第 10 节。

### 6.4 修正后的验证示例

原路径：`/电影库/阿凡达/[4K]阿凡达.2009.mp4`

```text
{grandparent}_{name.regex_replace('\[.*?\]', '').trim()}_{seq}{ext}
```

预览结果：`电影库_阿凡达.2009_1.mp4`

若用户用 `{parent}_{name...}{ext}`，结果是 `阿凡达_阿凡达.2009.mp4`。界面必须把每个占位符的当前值显示出来。

### 6.5 预览与执行

1. 结果表固定有 from / to / reason。
2. 非法字符、空文件名、超长路径、目标冲突，行级标红，默认不执行这些行。
3. 目录改名和文件改名可以同一次计划，计划器按先深后浅排序，并用虚拟 FS 计算最终路径。
4. `{seq}` 按最终计划勾选行编号，取消勾选后默认重排。

验收：不写代码也能完成 `a/b/c/a.txt -> b.txt` 或 `c.txt`；清洗函数可去掉 `[4K]` / `WEB-DL`；Dry-Run 与执行一致；目标已存在时走全局冲突策略，不静默覆盖。

## 7. 模块五：智能缩略图快速预览（透视眼）

1. 图片：v1 目标是 `sharp` 生成 128x128 WebP。v1.8.0 实际用 Electron `nativeImage` 生成 192x192 JPEG，经 Preview Worker 落盘到 `%APPDATA%/Nestify/cache/thumbnails`。
2. 视频：v1 目标是 `fluent-ffmpeg` 抽第一帧。当前只返回 file URL 播放，不生成视频缩略图。
3. 列表虚拟滚动，只渲染可视区 + 少量预取。
4. 当前选中项预览优先于后台缩略图生成。
5. 缓存键：`entry_id + size + mtime + generator_version`，不能只用绝对路径。文件改名后旧缓存仍应能命中。
6. ffmpeg 未安装时：图片预览仍可用，视频显示类型图标，提示安装/启用组件，并允许系统默认程序打开。
7. NAS/SMB：缩略图并发默认 1-2，失败重试有限，滚动时取消出屏任务。
8. 重复对比和改名审核都复用同一预览组件。

验收：滚动图片列表不因解码卡死；同一文件改名后缩略图仍在；视频第一帧生成失败有明确原因，不空白。

## 8. 模块六：一键目录自动归类（筑巢模式）

这 5 条作为内置方案 `默认下载整理` 提供，默认全部 Dry-Run，第 4 条默认禁用。

| 优先级 | 规则 ID | IF | THEN | 默认 | 修订 |
| --- | --- | --- | --- | --- | --- |
| 1 | `rename-dir-from-single-video` | 文件夹内有效视频恰好 1 个，且文件夹名不等于视频 stem；忽略 nfo/封面/字幕 | 文件夹改名为视频 stem | 启用 | sidecar 不阻止命中 |
| 2 | `flatten-single-child-dir` | 文件夹内只有 1 个子文件夹，无其他有效文件 | 子文件夹内容上移，删除空壳 | 启用 | 若子目录名更有信息，可选择保留子名到父级 |
| 3 | `strip-release-tags` | 文件名包含 []、1080P、2160P、4K、WEB-DL、BluRay 等标签 | 正则清洗，保留片名和年份 | 启用 | 只改名不移动 |
| 4 | `move-videos-to-videos-folder` | 扩展名 in mp4,mkv,avi,mov | 移入用户指定目录，默认 `{library}/Videos`，不是盘符根 Videos | 禁用 | 必须可改目标；默认不拆散同名文件夹 |
| 5 | `archive-already-extracted` | 扩展名 in zip,rar,7z，且同名文件夹存在 | 默认移入 `{library}/__已解压源文件__`；用户可改隔离区或删除到回收站 | 启用，动作为隔离 | 只有 same_payload_confidence >= 0.9 才允许删除选项生效 |

额外内置但不默认启用：空目录清理；无意义目录名（新建文件夹 / New Folder / 未命名）；临时下载文件忽略（`.xltd` `.part` `.!qB`）。

验收：用户能禁用任一条、改优先级、另存为影视方案；点执行先出变更清单；第 4 条未启用时不会把视频搬到盘符根；第 1 条不会因为旁边有 jpg 封面就失效。

## 9. 规则流交互（全局）

### 9.1 Profile 方案

1. 用户可建多个方案：影视方案、工作文档方案、下载收件箱。
2. 方案内规则有序，可启用/禁用。
3. 执行时选方案 + 作用域（整个库 / 当前目录 / 当前勾选）。
4. 方案导入导出 YAML。外部方案含 delete/quarantine 时，导入后默认强制 Dry-Run。

### 9.2 Dry-Run 预览表

执行任何写操作前必须出现清单，列：序号、原路径、新路径、操作类型（改名/移动/删除/隔离/拍平/创建目录）、命中规则、风险、勾选框。

能力：默认全选低风险行，冲突/覆盖行默认不选；取消任意行；按操作类型/规则/风险过滤；抽样预览当前行；统计将改名/移动/删除/冲突数量；确认执行后才写盘。

### 9.3 冲突策略

当目标已存在：

1. 自动追加序号（默认）：`xxx.txt` -> `xxx (1).txt`，若仍冲突继续 `(2)`
2. 跳过：保留原文件，记日志
3. 覆盖：默认关闭。选择后必须显式确认“覆盖 N 个文件”，计划表标红。不做密码框。
4. 方案级可设默认策略，执行前仍可改。
5. 目录与文件互相占名、大小写冲突、Windows 非法名都算冲突，不能当普通 skip 藏过去。

执行后生成任务报告，支持按任务回滚，索引增量更新，不需要全库重扫。
