# Nestify 媒体合并模块 TRD

> 文档版本：v1.1
> 日期：2026-09-22
> 模块：媒体合并（Media Merge）
> 状态：功能实现完成，进入最终验证阶段
> 关联模块：文件搜索、任务中心、设置、媒体预览、桌面打包

## 1. 文档目的

本文定义 Nestify 的图片拼接与视频顺序合并能力。该模块的定位不是通用视频剪辑软件，而是在已有本地文件治理流程中，把一组用户明确选择的媒体文件，按可解释的顺序合成为一个新的输出文件。

核心流程：

```text
选择媒体
  -> 排序
  -> 视频头尾裁剪与音频设置
  -> 输出设置与风险确认
  -> 后台执行
  -> 查看结果 / 恢复失败任务
```

本文同时记录当前实现状态、页面结构、数据模型、执行边界和失败恢复策略。后续新增能力必须先补充本文，再进入实现，避免页面文案与真实能力脱节。

## 2. 问题定义

用户经常面对两类重复劳动：

1. 若干截图、照片或扫描页需要合成一张长图或网格图。
2. 若干视频片段需要按拍摄顺序拼接，每个片段开头或结尾可能有多余部分需要去掉。

本模块解决的问题是：

- 输入来源明确，不自动猜测用户想合并哪些文件。
- 顺序来源明确，用户知道结果来自手动顺序、规则顺序还是规则加手工钉选。
- 裁剪来源明确，用户知道每个视频使用批量设置还是自定义设置。
- 音频调整有清晰边界，快速流复制与重新编码的能力差异必须前置说明。
- 合并前能看见预计输出、数量、时长、尺寸和风险。
- 合并执行在 Electron Main / Node 后台完成，不能造成渲染端未响应。
- 只新增输出文件，不移动、删除或覆盖源文件。
- 失败后可解释；可恢复任务必须能从持久化工作区继续，用户取消则清理现场。

## 3. 版本能力边界

### 3.1 当前支持

素材与顺序：

- 独立“合并”工作区页签。
- 从搜索勾选结果导入图片或视频。
- 手动添加本地文件。
- 视频任务可以加入图片。图片任务不能加入视频。
- 手动排序、规则排序、规则加手工钉选。
- 规则包含文件名自然排序、名称数字排序、修改时间排序、路径排序。
- 重复路径导入去重。

图片输出：

- 纵向长图。
- 横向长图。
- 网格拼图。
- JPG、PNG、WebP 输出。
- 统一宽度或统一高度。
- 白色或透明背景。
- 可设置间距和网格列数。
- 执行前计算输出尺寸，单边不超过 32767px，总像素不超过 1 亿。

视频输出：

- MP4、MOV、MKV、WebM、AVI、TS 输出。
- 每个视频可裁掉开头和结尾。
- 视频任务中的图片可单独设置停留秒数（0.2 到 120 秒，默认 3 秒）和出现方式：静止、淡入淡出、缓慢放大、缓慢缩小、从左向右、从右向左。
- 图片按黑底居中进入视频，本身没有声音。
- 批量默认裁剪、单个视频自定义裁剪、恢复批量设置。
- 边预览边调整起点和终点。
- 时间轴抽帧与音频波形。
- 播放保留区间、循环保留区间、按当前位置设置起点或终点。
- 单素材音量、静音、音频淡入、音频淡出。
- 全局输出音量与全局静音。
- 交叉淡化转场，时长 0.1 到 5 秒。
- 默认重新编码，保证不同来源视频可拼接。
- 自动或手动快速流复制；只有所有输入参数高度一致时可用。
- FFmpeg 与 FFprobe 随应用打包，无需用户单独安装。

执行与任务：

- 后台任务、阶段进度、取消。
- 任务持久化到任务中心。
- 图片图层和视频分段支持断点工作区。
- 异常中断后可校验 checkpoint 和 manifest 并显式恢复。
- 输出同名冲突自动追加序号。
- 成功前写临时文件，成功后原子重命名。

### 3.2 明确不做

当前版本不提供以下能力，界面也不暗示支持：

- 把视频加入图片长图。
- 图片裁剪、加边框、水印、调色、模板拼图。
- 字幕、贴纸、滤镜、画中画、关键帧动画。
- 多音轨、音量曲线、配音、语音识别。
- 4K / 8K 实时预览剪辑。
- 从视频抽帧后再进入图片合并。
- 合并后自动删除源文件。
- 覆盖输出文件。
- 生成任务回滚。合并是新增输出，不是源文件改造；失败恢复只针对未完成输出。
- 自动扫描并推荐“可能属于一组”的媒体。

### 3.3 精度与兼容边界

- 视频裁剪输入精度为 0.01 秒，界面常用步进为 0.1 秒。
- HTML video 预览帧与 FFmpeg 最终编码帧可能存在毫秒级差异，最终以 FFmpeg 输出为准。
- 重新编码统一分辨率、帧率、像素格式和音频参数，是跨来源合并的可靠性路径。
- 快速流复制不重新编码，裁剪精度受容器关键帧和 concat demuxer 影响；需要精确裁剪时必须使用重新编码。
- 快速流复制要求所有视频为 H.264、相同 profile、分辨率、帧率、像素格式、timebase，且音频参数一致；部分输入无音频时也不可用。
- 快速流复制与转场、全局音量、单素材音量、静音、淡入淡出互斥。
- 图片尺寸来自解码后的真实像素，并应用 EXIF 方向。
- 预计输出尺寸在执行前计算；源文件在执行前被外部修改时，执行器必须重新校验并失败。
- JPG 不支持透明背景，选择透明时只对 PNG / WebP 有意义。
- 超大图片、超长视频、磁盘空间不足、输出目录消失、输入被删除或修改时，任务失败并返回明确错误，不生成假成功文件。

## 4. 用户流程与页面设计

### 4.1 信息架构

模块放在桌面主工作区一级页签，名称为“合并”。它不放入设置，也不作为整理或改名的附属按钮。

```text
文件 | 整理 | 改名 | 重复 | 合并 | 任务
```

页面固定为三步向导：

```text
1 选择素材 -> 2 排序 / 裁剪 -> 3 输出 / 确认
```

交互规则：

- 当前步骤只有一个主按钮。
- 主按钮文案说明去向，例如“下一步：排序和裁剪”。
- 上一步保留已选择的文件、排序和裁剪值。
- 执行期间页面只读，切换页签不取消任务。
- 页面宽度不足时按“步骤条、素材列表、属性面板、底部操作条”顺序纵向堆叠。

组件层级：

```text
MergePane
├── MergePickStep                    第 1 步：选择素材
│   ├── 来源工具条                   搜索导入、添加文件、清空
│   ├── 类型汇总                     图片数、视频数、阻塞原因
│   └── 素材表格                     文件、类型、大小、修改时间
├── MergeArrangeStep                 第 2 步：排序 / 裁剪
│   ├── MergeOrderControls           排序模式、规则、钉选控制
│   ├── 素材顺序列表                 拖拽、上移、下移、移除
│   ├── ImagePreview                 图片预览
│   └── VideoTrimEditor              视频属性面板
│       ├── HTML video 播放器
│       ├── MediaTrimTimeline        抽帧、波形、裁剪把手
│       ├── BatchTrimPanel           批量裁剪
│       └── VideoAudioControls       单素材音频
├── MergeOutputStep                  第 3 步：输出 / 确认
│   ├── 输出表单                     目录、文件名、格式、布局
│   ├── 视频高级设置                 编码、画质、音频、转场、音量
│   └── 执行摘要                     计划、警告、进度、结果
└── 底部操作条                       上一步、下一步、开始合并
```

状态管理由 `useMediaMerge` 承担，素材排序、路径、格式化等纯逻辑拆到 `media-merge-utils.ts`，界面组件只负责呈现和交互，避免单个 Hook 或组件继续膨胀。

### 4.2 第一步：选择素材

第一步回答三个问题：素材从哪里来、现在选了什么、能不能进入下一步。

```text
┌──────────────────────────────────────────────────────────────┐
│ 1 选择素材        2 排序 / 裁剪      3 输出 / 确认              │
├──────────────────────────────────────────────────────────────┤
│ [从搜索勾选导入] [添加文件] [清空]                              │
│                                                              │
│ 当前：12 个视频 / 0 张图片，总大小 2.4 GB                      │
├──────────────────────────────────────────────────────────────┤
│ #  文件名             类型   大小       修改时间                │
│ 1  morning.mp4        视频   312 MB    2026-09-20 08:12       │
│ 2  noon.mp4           视频   408 MB    2026-09-20 12:40       │
│ 3  night.mp4          视频   296 MB    2026-09-20 20:05       │
├──────────────────────────────────────────────────────────────┤
│                                              [下一步：排序和裁剪] │
└──────────────────────────────────────────────────────────────┘
```

规则：

- “从搜索勾选导入”只在存在搜索勾选或当前选中文件时可用。
- “添加文件”打开系统多选对话框，只显示图片和视频。
- 导入按扩展名分类，不做内容探测。
- 混合类型时保留全部输入，但主按钮禁用，汇总区显示阻塞原因。
- 每行提供移除按钮；移除只退出本次任务，不修改源文件。
- 图片少于两个、或视频一个都没有时，主按钮禁用。单个视频或单张图片可以单独导出。
- 重复路径导入时自动去重，并提示已忽略数量。
- 空态只提供动作入口，不展示无意义的空表格。
- 导入失败不静默清空已有素材，错误显示在行级或汇总提示中。

### 4.3 第二步：排序与裁剪

第二步采用左右布局。左侧是顺序，右侧是当前项属性。

```text
┌────────────────────────┬──────────────────────────────────────┐
│ 排序                   │ morning.mp4                          │
│ [手动] [规则排序]       │ 类型：视频 / 大小：312 MB             │
│ 规则：[文件名自然排序▼] │                                      │
│ [重新按规则排序]         │ ┌──────────────────────────────────┐ │
│                        │ │            视频画面                │ │
│ 01 morning.mp4         │ └──────────────────────────────────┘ │
│ 02 noon.mp4            │ 抽帧时间轴 + 波形 + 裁剪把手           │
│ 03 night.mp4           │                                      │
│                        │ [播放保留区间] [循环区间]               │
│ 批量状态               │ [当前设为开始] [当前设为结束]           │
│ 2 个批量裁剪            │ [恢复批量]                           │
│ 1 个自定义裁剪          │                                      │
│                        │ 批量裁剪 / 单素材音频                  │
└────────────────────────┴──────────────────────────────────────┘
```

排序语义：

- 手动模式下列表顺序就是最终输出顺序。
- 规则排序会重排未钉选素材；点击“重新按规则排序”会清除手工钉选。
- 在规则排序结果中拖拽某行时，该行进入手工钉选状态。
- 钉选行显示“手动位置”标记；存在钉选时汇总区显示规则加手工覆盖数量，并可清除覆盖。
- 上移、下移是拖拽的键盘等价操作。

视频裁剪语义：

- `trimStart` 表示从视频开头去掉的秒数。
- `trimEndOffset` 表示从视频结尾去掉的秒数，空值表示不去尾。
- 实际终点为 `duration - trimEndOffset`，批量设置可正确作用在不同时长的视频上。
- 保留区间必须至少 0.1 秒。
- 起点不能小于 0，终点不能大于原时长。
- 修改当前项裁剪值后，来源从“批量”变为“自定义”。
- “应用到未自定义”保留所有自定义项。
- “应用到全部”覆盖自定义裁剪值，但不覆盖单素材音频设置。
- “恢复批量”只恢复当前项裁剪，不影响音频设置。
- 视频无法被 Chromium 播放时，显示错误并保留数字裁剪表单，不阻塞任务。

视频音频语义：

- 单素材音量范围为 0 到 4 倍。
- 单素材可静音，可设置淡入和淡出。
- 淡入加淡出不能超过该素材裁剪后时长。
- 全局静音优先于单素材音频设置。
- 输出音量为 0 时输出无声视频。

图片任务此步骤只处理顺序和预览，不显示视频时间轴。

视频任务中的图片片段：

- 选中图片后显示停留秒数和出现方式，不显示视频裁剪轴。
- 停留秒数只影响当前图片，范围 0.2 到 120 秒。
- 出现方式在合成时生效：静止保持画面，淡入淡出在片段首尾过渡，放大和缩小使用中心缩放，平移在略放大的画面上从一侧移动到另一侧。
- 预览按停留秒数播放静止画面，不模拟镜头运动。


### 4.4 第三步：输出设置

第三步分为输出表单和执行摘要两栏。

图片设置：

- 输出目录。
- 输出文件名。
- 布局：纵向长图、横向长图、网格拼图。
- 格式：JPG、PNG、WebP。
- 纵向和网格使用统一宽度；横向使用统一高度。
- 网格列数 1 到 8。
- 间距 0 到 128px。
- 背景白色或透明。

视频设置：

- 输出目录。
- 输出文件名。
- 输出格式：MP4、MOV、MKV、WebM、AVI、TS。
- 编码模式：自动、重新编码、快速流复制。
- 画质：标准、高画质。
- 音频：保留、静音。
- 转场：无、交叉淡化。
- 转场时长 0.1 到 5 秒。
- 输出音量 0 到 4 倍。

输出冲突永远自动追加序号，不提供覆盖。

摘要内容：

- 输入数量。
- 顺序来源。
- 图片预计输出尺寸与布局。
- 视频原总时长、裁剪后总时长、转场后输出时长。
- 批量裁剪与自定义裁剪数量。
- 输出路径。
- 超大输出、快速流复制互斥、全部静音等提示。

### 4.5 执行状态

点击开始后进入执行状态，不再显示可编辑表单。

```text
正在合并视频

校验输入        完成
分析媒体        完成
编码输出        46%
收尾写入        等待

当前阶段：FFmpeg 编码
[取消任务]
```

执行状态规则：

- `start` 只创建任务并返回 `jobId`，不等待合成完成。
- 渲染端可切换页签，任务继续执行。
- 用户取消会中止 FFmpeg 或图片处理，并清理临时输出和工作区。
- 失败后显示具体失败阶段和错误。
- 成功只有在输出完成重命名并通过存在性校验后才允许显示。
- 成功后显示输出路径和“查看文件”。
- 任务详情进入任务中心，可查看进度、断点阶段和失败原因。

用户取消与异常中断必须区分：

- 用户取消：视为主动放弃，删除半成品和断点工作区。
- 异常中断：例如进程崩溃、断电、FFmpeg 非零退出；保留工作区、checkpoint 和 manifest，任务标记失败，允许用户显式恢复。

### 4.6 响应式与可访问性

- 1024px 以上：第二步保持“顺序列表 / 属性面板”左右布局，第三步保持“输出表单 / 摘要”左右布局。
- 768px 到 1024px：顺序列表与属性面板上下排列，视频预览保持在首屏内。
- 768px 以下：步骤条压缩，表格隐藏次要列，操作条跟随内容，不悬浮遮挡。
- 预览播放器保持稳定比例，加载后不允许把时间轴挤出可视区。
- 时间轴把手可点击区域不小于 24px。
- 图标按钮提供 `title` 和 `aria-label`。
- 上移、下移、设为起点、设为终点可键盘操作。
- 进度提供文本百分比，不只依赖颜色。

## 5. 数据模型

核心类型定义在 `packages/shared/src/media.ts`，桌面端与 core 共用，避免 IPC 边界重复定义。

```ts
type MediaMergeKind = 'image' | 'video'

type MediaMergeOrderRule =
  | 'manual'
  | 'name-natural'
  | 'name-number'
  | 'mtime'
  | 'path'

type MediaMergeTrimSource = 'batch' | 'custom'

interface MediaMergeItem {
  id: string
  path: string
  kind: MediaMergeKind
  size: number
  mtime: number | null
  trimStart: number
  trimEndOffset: number | null
  trimSource: MediaMergeTrimSource
  orderIndex: number
  manualOrder: boolean
  volume?: number
  muted?: boolean
  audioFadeInSeconds?: number
  audioFadeOutSeconds?: number
}

interface MediaMergeImageSettings {
  format: 'jpg' | 'png' | 'webp'
  layout: 'vertical' | 'horizontal' | 'grid'
  width: number
  height: number
  columns: number
  gap: number
  background: 'white' | 'transparent'
}

interface MediaMergeVideoSettings {
  quality: 'standard' | 'high'
  audio: 'keep' | 'mute'
  encodingMode: 'auto' | 'reencode' | 'stream-copy'
  transition: { type: 'none' | 'crossfade'; durationSeconds: number }
  outputVolume: number
}
```

计划校验规则：

- 图片任务至少两个图片文件。视频任务至少一个视频或图片。
- 输入路径必须是绝对路径且真实存在。
- 输入文件不能重复。
- 输出路径不能等于任何输入路径。
- 输出目录必须存在并可写。
- 输出文件名不能为空，不能包含路径分隔符。
- 图片统一宽高范围 16 到 8192。
- 图片间距范围 0 到 128。
- 图片输出单边不超过 32767px。
- 图片总像素不超过 1 亿。
- 视频剩余时长必须大于 0.1 秒。
- 裁剪值不能为负。
- 转场时长不能超过相邻两个裁剪后片段中较短的一个。
- 单素材淡入加淡出不能超过其裁剪后时长。
- 快速流复制必须满足编码、profile、分辨率、帧率、像素格式、timebase 和音频兼容条件。

## 6. 技术设计

### 6.1 进程职责

Renderer：

- 维护合并草稿状态。
- 拖拽排序和表单输入。
- HTML video 预览、seek、播放保留区间。
- 时间轴与波形展示。
- 展示计划摘要和任务进度。

Electron Main：

- 文件与目录选择对话框。
- IPC 转发。
- 媒体文件安全读取协议。
- 初始化内置 FFmpeg / FFprobe 路径。
- 后台任务事件推送。

Core：

- 输入类型判断。
- 排序与计划校验。
- 输出路径分配。
- 图片分析与合成。
- 视频探测、分段、拼接、转场和音频处理。
- FFmpeg 进度解析、取消、checkpoint、manifest、恢复。

渲染端不直接调用 Node API，不扫描磁盘，不探测 FFmpeg，不拼接命令行。可能阻塞或访问文件系统的工作全部进入 Electron Main 或 core。

### 6.2 图片合成

执行流程：

```text
逐张读取元信息
  -> 应用 EXIF 方向
  -> 计算布局与输出尺寸
  -> 逐张缩放为图层
  -> 按布局写入工作区
  -> composite 生成临时输出
  -> 校验后原子重命名
```

布局算法：

- 纵向：所有图片缩放到统一宽度，从上到下排列。
- 横向：所有图片缩放到统一高度，从左到右排列。
- 网格：按列数计算单元格宽度，行内垂直居中，行高取该行最高图片。

断点工作区保存每个图层 PNG 和已完成阶段。恢复时已存在的图层直接读取，未完成的图层重新生成，最终重新合成。

### 6.3 视频拼接

重新编码流程：

```text
ffprobe 读取每个视频
  -> 校验裁剪与音频边界
  -> 生成每个分段
  -> 统一分辨率、帧率、像素格式和音频参数
  -> concat / xfade 拼接
  -> 输出 H.264 + AAC MP4
  -> 原子重命名
```

细节：

- 分辨率取所有输入最大宽高并转为偶数，等比缩小后黑边居中。
- 帧率限制在 24 到 60fps。
- 视频统一输出 `yuv420p`。
- 音频统一重采样到 48kHz 立体声。
- 需要保留输出音频但部分素材不可听时，使用 `anullsrc` 补齐静音轨，保证 concat / acrossfade 输入稳定。
- 交叉淡化使用视频 `xfade` 与音频 `acrossfade`，输出时长扣除每个转场重叠。
- 全部不可听或全局静音时输出 `-an`。
- 进度通过 `-progress pipe:1` 解析。
- FFmpeg 参数使用数组传递，不拼 shell 字符串。

快速流复制流程：

```text
ffprobe 读取所有输入
  -> 校验编码与流参数一致
  -> 校验没有转场和音频调整
  -> 生成 concat 列表
  -> FFmpeg stream copy
  -> 原子重命名
```

快速流复制适合来源相同的整段素材。跨设备、不同编码、不同分辨率、不同帧率或需要精确裁剪时，应使用重新编码。

### 6.4 内置 FFmpeg 分发

FFmpeg 不作为源码仓库二进制提交，而由 npm 受管依赖安装并在打包前复制：

- `ffmpeg-static@5.3.0` 提供 FFmpeg，当前 Windows 二进制为 6.1.1。
- `@ffprobe-installer/ffprobe@2.1.2` 按平台提供 FFprobe。
- `prepare:ffmpeg` 复制可执行文件和许可文本到 `apps/desktop/resources/ffmpeg`。
- `build` 与 `dist:artifact` 前自动执行准备脚本。
- 根目录 `postinstall` 会执行打包，因此干净环境执行 `npm install` 后会生成 release exe。
- `resources/ffmpeg` 被 git 忽略，避免提交上百 MB 二进制。
- `extraResources` 会把整个 `resources` 目录复制进安装包。

运行时查找顺序：

1. `NESTIFY_FFMPEG_PATH` / `NESTIFY_FFPROBE_PATH` 环境变量。
2. 应用内置 `resources/ffmpeg`。
3. 系统 PATH。

用户显式设置的环境变量优先，便于测试替换 FFmpeg 版本。许可文本见 `apps/desktop/resources/third-party-notices.md` 及打包资源内同目录的 `ffmpeg.LICENSE.txt`、`ffprobe.LICENSE.txt`。

### 6.5 预览与文件访问契约

图片和视频预览通过 Electron Main 明确开放的媒体读取通道访问，不允许渲染端使用任意 `file://` 路径。

授权规则：

- 请求必须携带目标路径与当前合并草稿中的完整路径列表。
- 目标路径必须存在于草稿列表，否则返回 `none`。
- Main 进程重新校验扩展名、绝对路径与文件状态。
- 从素材列表移除文件后，后续预览请求返回 `none`。
- 输出路径不是输入素材，不能通过该通道读取。

时间轴抽帧：

- 每个视频取 4 到 12 帧。
- 使用 FFmpeg 输出 JPEG 到管道，不落临时文件。
- 帧图以受限 data URL 返回渲染端。

音频波形：

- FFprobe 先确认是否存在音频流。
- FFmpeg 转单声道 8kHz PCM 到管道。
- Core 计算 32 到 600 个峰值并归一化。
- 无音频或失败时返回可解释错误，不阻塞视频裁剪。

Chromium 无法解码的格式可以显示“无法预览”，但数字裁剪和执行仍可继续；执行前仍必须通过 FFprobe 探测。

### 6.6 IPC 契约

```text
mediaMerge.selectFiles       打开图片 / 视频多选对话框
mediaMerge.selectDirectory   选择输出目录
mediaMerge.buildPlan         校验并生成计划
mediaMerge.start             创建后台任务并返回 jobId
mediaMerge.cancel            请求取消任务
mediaMerge.progress          查询进度
mediaMerge.preview           为草稿内文件生成受限预览
mediaMerge.timeline          为草稿内视频生成抽帧时间轴
mediaMerge.waveform          为草稿内视频生成音频波形
mediaMerge.resume            从失败任务的 checkpoint 恢复
```

请求与返回包含稳定的 `jobId` 或目标路径；渲染端忽略过期响应。进度事件节流，避免高频 IPC 压垮渲染端。

### 6.7 恢复设计

每个可恢复任务拥有独立工作区：

```text
workspace
├── manifest.json             计划指纹、输入状态、阶段、输出路径
├── layer-00000.png           图片任务图层缓存
└── segment-00000.mp4         视频任务分段缓存
```

checkpoint 与 manifest 必须同时校验：

- 版本一致。
- 任务 ID 一致。
- 工作区路径一致。
- 首选输出路径一致。
- 阶段数量和已完成阶段一致。
- 计划指纹一致。
- 输入路径、大小、修改时间一致。

任何一项不匹配都拒绝恢复，避免把旧分段拼入新计划。恢复时已完成的图片图层或视频分段直接复用，未完成阶段重新执行，最终重新合成并原子重命名。

## 7. 安全与失败边界

- 不修改源文件。
- 不覆盖输出文件，自动追加 `-1`、`-2`。
- 输出临时文件放在输出目录附近，成功后原子重命名。
- 用户取消或不可恢复失败时清理临时文件和工作区。
- 执行前重新 `stat` 输入，发现缺失或修改时间变化即失败。
- FFmpeg 参数数组传递，路径只传给子进程，不拼接命令解释器。
- 输出目录必须显式选择，不写入隐藏目录。
- 任务失败不能留下假装成功的输出文件。
- 内置 FFmpeg 和 FFprobe 只用于本模块媒体处理，不用于执行任意用户命令。

## 8. 验收标准

### 8.1 图片

- 3 张不同宽度图片按纵向布局输出，宽度等于设置值，顺序与列表一致。
- 横向布局输出高度等于设置值，顺序与列表一致。
- 网格布局列数、间距和行内顺序正确。
- PNG 透明背景不变成黑色。
- 超过尺寸或像素限制时执行前失败并给出建议。
- 输出同名时自动追加序号。
- 取消后没有临时文件、图层工作区和半成品。

### 8.2 视频

- 3 个不同分辨率 MP4 输出一个可播放 MP4。
- 每个视频头尾裁剪生效，总时长约等于各剩余时长之和。
- 交叉淡化生效，输出时长扣除转场重叠。
- 单素材音量、静音、淡入淡出生效。
- 部分无音频素材在保留音频输出时自动补静音轨。
- 边预览边调整裁剪时界面不阻塞。
- 快速流复制在不兼容或与音频调整互斥时返回明确错误或提示。
- 取消后没有半成品输出。
- 合并期间切换页面不中断任务。

### 8.3 执行与恢复

- 混合图片和视频时无法进入下一步。
- 规则排序后列表顺序与计划顺序一致。
- 批量应用不覆盖推荐范围内的自定义裁剪。
- 应用到全部覆盖裁剪值但保留单素材音频设置。
- 执行摘要中的数量、路径、时长和尺寸与实际计划一致。
- 任务中心能查看失败原因、断点阶段和输出信息。
- checkpoint 或 manifest 不匹配时拒绝恢复。
- 可恢复任务恢复后不重复生成已完成图层或分段。
