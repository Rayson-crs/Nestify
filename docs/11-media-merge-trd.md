# Nestify 媒体合并模块 TRD

> 文档版本：v1.2
> 日期：2026-09-23
> 模块：媒体合并（Media Merge）
> 状态：主流程已实现。第 9 节里程碑保留已完成记录；当前缺口和后续修改以第 10 节为准，第 10 节尚未开始改代码。
> 关联模块：文件搜索、任务中心、设置、媒体预览、桌面打包

## 1. 文档目的

本文定义 Nestify 的图片拼接与视频顺序合并能力。该模块的定位不是通用视频剪辑软件，而是在已有本地文件治理流程中，把一组用户明确选择的媒体文件，按可解释的顺序合成为一个新的输出文件。

核心流程：

```text
选择媒体
  -> 排序
  -> 视频头尾裁剪与音频设置
  -> 输出设置与风险确认
  -> 后台执行
  -> 查看结果 / 恢复失败任务
```

本文同时记录当前实现状态、页面结构、数据模型、执行边界和失败恢复策略。后续新增能力必须先补充本文，再进入实现，避免页面文案与真实能力脱节。

## 2. 问题定义

用户经常面对两类重复劳动：

1. 若干截图、照片或扫描页需要合成一张长图或网格图。
2. 若干视频片段需要按拍摄顺序拼接，每个片段开头或结尾可能有多余部分需要去掉。

本模块解决的问题是：

- 输入来源明确，不自动猜测用户想合并哪些文件。
- 顺序来源明确，用户知道结果来自手动顺序、规则顺序还是规则加手工钉选。
- 裁剪来源明确，用户知道每个视频使用批量设置还是自定义设置。
- 音频调整有清晰边界，快速流复制与重新编码的能力差异必须前置说明。
- 合并前能看见预计输出、数量、时长、尺寸和风险。
- 合并执行在 Electron Main / Node 后台完成，不能造成渲染端未响应。
- 只新增输出文件，不移动、删除或覆盖源文件。
- 失败后可解释；可恢复任务必须能从持久化工作区继续，用户取消则清理现场。

## 3. 版本能力边界

### 3.1 当前支持

素材与顺序：

- 独立“合并”工作区页签。
- 从搜索勾选结果导入图片或视频。
- 手动添加本地文件。
- 视频任务可以加入图片。图片任务不能加入视频。
- 手动排序、规则排序、规则加手工钉选。
- 规则包含文件名自然排序、名称数字排序、修改时间排序、路径排序。
- 重复路径导入去重。

图片输出：

- 纵向长图。
- 横向长图。
- 网格拼图。
- JPG、PNG、WebP 输出。
- 统一宽度或统一高度。
- 白色或透明背景。
- 可设置间距和网格列数。
- 执行前计算输出尺寸，单边不超过 32767px，总像素不超过 1 亿。

视频输出：

- MP4、MOV、MKV、WebM、AVI、TS 输出。
- 每个视频可裁掉开头和结尾。
- 视频任务中的图片可单独设置停留秒数（0.2 到 120 秒，默认 3 秒）和出现方式：静止、淡入淡出、缓慢放大、缓慢缩小、从左向右、从右向左。
- 图片按黑底居中进入视频，本身没有声音。
- 批量默认裁剪、单个视频自定义裁剪、恢复批量设置。
- 边预览边调整起点和终点。
- 时间轴抽帧与音频波形。
- 播放保留区间、循环保留区间、按当前位置设置起点或终点。
- 单素材音量、静音、音频淡入、音频淡出。
- 全局输出音量与全局静音。
- 交叉淡化转场，时长 0.1 到 5 秒。
- 默认重新编码，保证不同来源视频可拼接。
- 自动或手动快速流复制；只有所有输入参数高度一致时可用。
- FFmpeg 与 FFprobe 随应用打包，无需用户单独安装。

执行与任务：

- 后台任务、阶段进度、取消。
- 任务持久化到任务中心。
- 图片图层和视频分段支持断点工作区。
- 异常中断后可校验 checkpoint 和 manifest 并显式恢复。
- 输出同名冲突自动追加序号。
- 成功前写临时文件，成功后原子重命名。

### 3.2 明确不做

当前版本不提供以下能力，界面也不暗示支持：

- 把视频加入图片长图。
- 图片裁剪、加边框、水印、调色、模板拼图。
- 字幕、贴纸、滤镜、画中画、关键帧动画。
- 多音轨、音量曲线、配音、语音识别。
- 4K / 8K 实时预览剪辑。
- 从视频抽帧后再进入图片合并。
- 合并后自动删除源文件。
- 覆盖输出文件。
- 生成任务回滚。合并是新增输出，不是源文件改造；失败恢复只针对未完成输出。
- 自动扫描并推荐“可能属于一组”的媒体。

### 3.3 精度与兼容边界

- 视频裁剪输入精度为 0.01 秒，界面常用步进为 0.1 秒。
- HTML video 预览帧与 FFmpeg 最终编码帧可能存在毫秒级差异，最终以 FFmpeg 输出为准。
- 重新编码统一分辨率、帧率、像素格式和音频参数，是跨来源合并的可靠性路径。
- 快速流复制不重新编码，裁剪精度受容器关键帧和 concat demuxer 影响；需要精确裁剪时必须使用重新编码。
- 快速流复制要求所有视频为 H.264、相同 profile、分辨率、帧率、像素格式、timebase，且音频参数一致；部分输入无音频时也不可用。
- 快速流复制与转场、全局音量、单素材音量、静音、淡入淡出互斥。
- 图片尺寸来自解码后的真实像素，并应用 EXIF 方向。
- 预计输出尺寸在执行前计算；源文件在执行前被外部修改时，执行器必须重新校验并失败。
- JPG 不支持透明背景，选择透明时只对 PNG / WebP 有意义。
- 超大图片、超长视频、磁盘空间不足、输出目录消失、输入被删除或修改时，任务失败并返回明确错误，不生成假成功文件。

## 4. 用户流程与页面设计

### 4.1 信息架构

模块放在桌面主工作区一级页签，名称为“合并”。它不放入设置，也不作为整理或改名的附属按钮。

```text
文件 | 整理 | 改名 | 重复 | 合并 | 任务
```

页面固定为三步向导：

```text
1 选择素材 -> 2 排序 / 裁剪 -> 3 输出 / 确认
```

交互规则：

- 当前步骤只有一个主按钮。
- 主按钮文案说明去向，例如“下一步：排序和裁剪”。
- 上一步保留已选择的文件、排序和裁剪值。
- 执行期间页面只读，切换页签不取消任务。
- 页面宽度不足时按“步骤条、素材列表、属性面板、底部操作条”顺序纵向堆叠。

组件层级：

```text
MergePane
├── MergePickStep                    第 1 步：选择素材
│   ├── 来源工具条                   搜索导入、添加文件、清空
│   ├── 类型汇总                     图片数、视频数、阻塞原因
│   └── 素材表格                     文件、类型、大小、修改时间
├── MergeArrangeStep                 第 2 步：排序 / 裁剪
│   ├── MergeOrderControls           排序模式、规则、钉选控制
│   ├── 素材顺序列表                 拖拽、上移、下移、移除
│   ├── ImagePreview                 图片预览
│   └── VideoTrimEditor              视频属性面板
│       ├── HTML video 播放器
│       ├── MediaTrimTimeline        抽帧、波形、裁剪把手
│       ├── BatchTrimPanel           批量裁剪
│       └── VideoAudioControls       单素材音频
├── MergeOutputStep                  第 3 步：输出 / 确认
│   ├── 输出表单                     目录、文件名、格式、布局
│   ├── 视频高级设置                 编码、画质、音频、转场、音量
│   └── 执行摘要                     计划、警告、进度、结果
└── 底部操作条                       上一步、下一步、开始合并
```

状态管理由 `useMediaMerge` 承担，素材排序、路径、格式化等纯逻辑拆到 `media-merge-utils.ts`，界面组件只负责呈现和交互，避免单个 Hook 或组件继续膨胀。

### 4.2 第一步：选择素材

第一步回答三个问题：素材从哪里来、现在选了什么、能不能进入下一步。

```text
┌──────────────────────────────────────────────────────────────┐
│ 1 选择素材        2 排序 / 裁剪      3 输出 / 确认              │
├──────────────────────────────────────────────────────────────┤
│ [从搜索勾选导入] [添加文件] [清空]                              │
│                                                              │
│ 当前：12 个视频 / 0 张图片，总大小 2.4 GB                      │
├──────────────────────────────────────────────────────────────┤
│ #  文件名             类型   大小       修改时间                │
│ 1  morning.mp4        视频   312 MB    2026-09-20 08:12       │
│ 2  noon.mp4           视频   408 MB    2026-09-20 12:40       │
│ 3  night.mp4          视频   296 MB    2026-09-20 20:05       │
├──────────────────────────────────────────────────────────────┤
│                                              [下一步：排序和裁剪] │
└──────────────────────────────────────────────────────────────┘
```

规则：

- “从搜索勾选导入”只在存在搜索勾选或当前选中文件时可用。
- “添加文件”打开系统多选对话框，只显示图片和视频。
- 导入按扩展名分类，不做内容探测。
- 混合类型时保留全部输入，但主按钮禁用，汇总区显示阻塞原因。
- 每行提供移除按钮；移除只退出本次任务，不修改源文件。
- 图片少于两个、或视频一个都没有时，主按钮禁用。单个视频或单张图片可以单独导出。
- 重复路径导入时自动去重，并提示已忽略数量。
- 空态只提供动作入口，不展示无意义的空表格。
- 导入失败不静默清空已有素材，错误显示在行级或汇总提示中。

### 4.3 第二步：排序与裁剪

第二步采用左右布局。左侧是顺序，右侧是当前项属性。

```text
┌────────────────────────┬──────────────────────────────────────┐
│ 排序                   │ morning.mp4                          │
│ [手动] [规则排序]       │ 类型：视频 / 大小：312 MB             │
│ 规则：[文件名自然排序▼] │                                      │
│ [重新按规则排序]         │ ┌──────────────────────────────────┐ │
│                        │ │            视频画面                │ │
│ 01 morning.mp4         │ └──────────────────────────────────┘ │
│ 02 noon.mp4            │ 抽帧时间轴 + 波形 + 裁剪把手           │
│ 03 night.mp4           │                                      │
│                        │ [播放保留区间] [循环区间]               │
│ 批量状态               │ [当前设为开始] [当前设为结束]           │
│ 2 个批量裁剪            │ [恢复批量]                           │
│ 1 个自定义裁剪          │                                      │
│                        │ 批量裁剪 / 单素材音频                  │
└────────────────────────┴──────────────────────────────────────┘
```

排序语义：

- 手动模式下列表顺序就是最终输出顺序。
- 规则排序会重排未钉选素材；点击“重新按规则排序”会清除手工钉选。
- 在规则排序结果中拖拽某行时，该行进入手工钉选状态。
- 钉选行显示“手动位置”标记；存在钉选时汇总区显示规则加手工覆盖数量，并可清除覆盖。
- 上移、下移是拖拽的键盘等价操作。

视频裁剪语义：

- `trimStart` 表示从视频开头去掉的秒数。
- `trimEndOffset` 表示从视频结尾去掉的秒数，空值表示不去尾。
- 实际终点为 `duration - trimEndOffset`，批量设置可正确作用在不同时长的视频上。
- 保留区间必须至少 0.1 秒。
- 起点不能小于 0，终点不能大于原时长。
- 修改当前项裁剪值后，来源从“批量”变为“自定义”。
- “应用到未自定义”保留所有自定义项。
- “应用到全部”覆盖自定义裁剪值，但不覆盖单素材音频设置。
- “恢复批量”只恢复当前项裁剪，不影响音频设置。
- 视频无法被 Chromium 播放时，显示错误并保留数字裁剪表单，不阻塞任务。

视频音频语义：

- 单素材音量范围为 0 到 4 倍。
- 单素材可静音，可设置淡入和淡出。
- 淡入加淡出不能超过该素材裁剪后时长。
- 全局静音优先于单素材音频设置。
- 输出音量为 0 时输出无声视频。

图片任务此步骤只处理顺序和预览，不显示视频时间轴。

视频任务中的图片片段：

- 选中图片后显示停留秒数和出现方式，不显示视频裁剪轴。
- 停留秒数只影响当前图片，范围 0.2 到 120 秒。
- 出现方式在合成时生效：静止保持画面，淡入淡出在片段首尾过渡，放大和缩小使用中心缩放，平移在略放大的画面上从一侧移动到另一侧。
- 预览按停留秒数播放静止画面，不模拟镜头运动。


### 4.4 第三步：输出设置

第三步分为输出表单和执行摘要两栏。

图片设置：

- 输出目录。
- 输出文件名。
- 布局：纵向长图、横向长图、网格拼图。
- 格式：JPG、PNG、WebP。
- 纵向和网格使用统一宽度；横向使用统一高度。
- 网格列数 1 到 8。
- 间距 0 到 128px。
- 背景白色或透明。

视频设置：

- 输出目录。
- 输出文件名。
- 输出格式：MP4、MOV、MKV、WebM、AVI、TS。
- 编码模式：自动、重新编码、快速流复制。
- 画质：标准、高画质。
- 音频：保留、静音。
- 转场：无、交叉淡化。
- 转场时长 0.1 到 5 秒。
- 输出音量 0 到 4 倍。

输出冲突永远自动追加序号，不提供覆盖。

摘要内容：

- 输入数量。
- 顺序来源。
- 图片预计输出尺寸与布局。
- 视频原总时长、裁剪后总时长、转场后输出时长。
- 批量裁剪与自定义裁剪数量。
- 输出路径。
- 超大输出、快速流复制互斥、全部静音等提示。

### 4.5 执行状态

点击开始后进入执行状态，不再显示可编辑表单。

```text
正在合并视频

校验输入        完成
分析媒体        完成
编码输出        46%
收尾写入        等待

当前阶段：FFmpeg 编码
[取消任务]
```

执行状态规则：

- `start` 只创建任务并返回 `jobId`，不等待合成完成。
- 渲染端可切换页签，任务继续执行。
- 用户取消会中止 FFmpeg 或图片处理，并清理临时输出和工作区。
- 失败后显示具体失败阶段和错误。
- 成功只有在输出完成重命名并通过存在性校验后才允许显示。
- 成功后显示输出路径和“查看文件”。
- 任务详情进入任务中心，可查看进度、断点阶段和失败原因。

用户取消与异常中断必须区分：

- 用户取消：视为主动放弃，删除半成品和断点工作区。
- 异常中断：例如进程崩溃、断电、FFmpeg 非零退出；保留工作区、checkpoint 和 manifest，任务标记失败，允许用户显式恢复。

### 4.6 响应式与可访问性

- 1024px 以上：第二步保持“顺序列表 / 属性面板”左右布局，第三步保持“输出表单 / 摘要”左右布局。
- 768px 到 1024px：顺序列表与属性面板上下排列，视频预览保持在首屏内。
- 768px 以下：步骤条压缩，表格隐藏次要列，操作条跟随内容，不悬浮遮挡。
- 预览播放器保持稳定比例，加载后不允许把时间轴挤出可视区。
- 时间轴把手可点击区域不小于 24px。
- 图标按钮提供 `title` 和 `aria-label`。
- 上移、下移、设为起点、设为终点可键盘操作。
- 进度提供文本百分比，不只依赖颜色。

## 5. 数据模型

核心类型定义在 `packages/shared/src/media.ts`，桌面端与 core 共用，避免 IPC 边界重复定义。

```ts
type MediaMergeKind = 'image' | 'video'

type MediaMergeOrderRule =
  | 'manual'
  | 'name-natural'
  | 'name-number'
  | 'mtime'
  | 'path'

type MediaMergeTrimSource = 'batch' | 'custom'

interface MediaMergeItem {
  id: string
  path: string
  kind: MediaMergeKind
  size: number
  mtime: number | null
  trimStart: number
  trimEndOffset: number | null
  trimSource: MediaMergeTrimSource
  orderIndex: number
  manualOrder: boolean
  volume?: number
  muted?: boolean
  audioFadeInSeconds?: number
  audioFadeOutSeconds?: number
}

interface MediaMergeImageSettings {
  format: 'jpg' | 'png' | 'webp'
  layout: 'vertical' | 'horizontal' | 'grid'
  width: number
  height: number
  columns: number
  gap: number
  background: 'white' | 'transparent'
}

interface MediaMergeVideoSettings {
  quality: 'standard' | 'high'
  audio: 'keep' | 'mute'
  encodingMode: 'auto' | 'reencode' | 'stream-copy'
  transition: { type: 'none' | 'crossfade'; durationSeconds: number }
  outputVolume: number
}
```

计划校验规则：

- 图片任务至少两个图片文件。视频任务至少一个视频或图片。
- 输入路径必须是绝对路径且真实存在。
- 输入文件不能重复。
- 输出路径不能等于任何输入路径。
- 输出目录必须存在并可写。
- 输出文件名不能为空，不能包含路径分隔符。
- 图片统一宽高范围 16 到 8192。
- 图片间距范围 0 到 128。
- 图片输出单边不超过 32767px。
- 图片总像素不超过 1 亿。
- 视频剩余时长必须大于 0.1 秒。
- 裁剪值不能为负。
- 转场时长不能超过相邻两个裁剪后片段中较短的一个。
- 单素材淡入加淡出不能超过其裁剪后时长。
- 快速流复制必须满足编码、profile、分辨率、帧率、像素格式、timebase 和音频兼容条件。

## 6. 技术设计

### 6.1 进程职责

Renderer：

- 维护合并草稿状态。
- 拖拽排序和表单输入。
- HTML video 预览、seek、播放保留区间。
- 时间轴与波形展示。
- 展示计划摘要和任务进度。

Electron Main：

- 文件与目录选择对话框。
- IPC 转发。
- 媒体文件安全读取协议。
- 初始化内置 FFmpeg / FFprobe 路径。
- 后台任务事件推送。

Core：

- 输入类型判断。
- 排序与计划校验。
- 输出路径分配。
- 图片分析与合成。
- 视频探测、分段、拼接、转场和音频处理。
- FFmpeg 进度解析、取消、checkpoint、manifest、恢复。

渲染端不直接调用 Node API，不扫描磁盘，不探测 FFmpeg，不拼接命令行。可能阻塞或访问文件系统的工作全部进入 Electron Main 或 core。

### 6.2 图片合成

执行流程：

```text
逐张读取元信息
  -> 应用 EXIF 方向
  -> 计算布局与输出尺寸
  -> 逐张缩放为图层
  -> 按布局写入工作区
  -> composite 生成临时输出
  -> 校验后原子重命名
```

布局算法：

- 纵向：所有图片缩放到统一宽度，从上到下排列。
- 横向：所有图片缩放到统一高度，从左到右排列。
- 网格：按列数计算单元格宽度，行内垂直居中，行高取该行最高图片。

断点工作区保存每个图层 PNG 和已完成阶段。恢复时已存在的图层直接读取，未完成的图层重新生成，最终重新合成。

### 6.3 视频拼接

重新编码流程：

```text
ffprobe 读取每个视频
  -> 校验裁剪与音频边界
  -> 生成每个分段
  -> 统一分辨率、帧率、像素格式和音频参数
  -> concat / xfade 拼接
  -> 输出 H.264 + AAC MP4
  -> 原子重命名
```

细节：

- 分辨率取所有输入最大宽高并转为偶数，等比缩小后黑边居中。
- 帧率限制在 24 到 60fps。
- 视频统一输出 `yuv420p`。
- 音频统一重采样到 48kHz 立体声。
- 需要保留输出音频但部分素材不可听时，使用 `anullsrc` 补齐静音轨，保证 concat / acrossfade 输入稳定。
- 交叉淡化使用视频 `xfade` 与音频 `acrossfade`，输出时长扣除每个转场重叠。
- 全部不可听或全局静音时输出 `-an`。
- 进度通过 `-progress pipe:1` 解析。
- FFmpeg 参数使用数组传递，不拼 shell 字符串。

快速流复制流程：

```text
ffprobe 读取所有输入
  -> 校验编码与流参数一致
  -> 校验没有转场和音频调整
  -> 生成 concat 列表
  -> FFmpeg stream copy
  -> 原子重命名
```

快速流复制适合来源相同的整段素材。跨设备、不同编码、不同分辨率、不同帧率或需要精确裁剪时，应使用重新编码。

### 6.4 内置 FFmpeg 分发

FFmpeg 不作为源码仓库二进制提交，而由 npm 受管依赖安装并在打包前复制：

- `ffmpeg-static@5.3.0` 提供 FFmpeg，当前 Windows 二进制为 6.1.1。
- `@ffprobe-installer/ffprobe@2.1.2` 按平台提供 FFprobe。
- `prepare:ffmpeg` 复制可执行文件和许可文本到 `apps/desktop/resources/ffmpeg`。
- `build` 与 `dist:artifact` 前自动执行准备脚本。
- 根目录 `postinstall` 会执行打包，因此干净环境执行 `npm install` 后会生成 release exe。
- `resources/ffmpeg` 被 git 忽略，避免提交上百 MB 二进制。
- `extraResources` 会把整个 `resources` 目录复制进安装包。

运行时查找顺序：

1. `NESTIFY_FFMPEG_PATH` / `NESTIFY_FFPROBE_PATH` 环境变量。
2. 应用内置 `resources/ffmpeg`。
3. 系统 PATH。

用户显式设置的环境变量优先，便于测试替换 FFmpeg 版本。许可文本见 `apps/desktop/resources/third-party-notices.md` 及打包资源内同目录的 `ffmpeg.LICENSE.txt`、`ffprobe.LICENSE.txt`。

### 6.5 预览与文件访问契约

图片和视频预览通过 Electron Main 明确开放的媒体读取通道访问，不允许渲染端使用任意 `file://` 路径。

授权规则：

- 请求必须携带目标路径与当前合并草稿中的完整路径列表。
- 目标路径必须存在于草稿列表，否则返回 `none`。
- Main 进程重新校验扩展名、绝对路径与文件状态。
- 从素材列表移除文件后，后续预览请求返回 `none`。
- 输出路径不是输入素材，不能通过该通道读取。

时间轴抽帧：

- 每个视频取 4 到 12 帧。
- 使用 FFmpeg 输出 JPEG 到管道，不落临时文件。
- 帧图以受限 data URL 返回渲染端。

音频波形：

- FFprobe 先确认是否存在音频流。
- FFmpeg 转单声道 8kHz PCM 到管道。
- Core 计算 32 到 600 个峰值并归一化。
- 无音频或失败时返回可解释错误，不阻塞视频裁剪。

Chromium 无法解码的格式可以显示“无法预览”，但数字裁剪和执行仍可继续；执行前仍必须通过 FFprobe 探测。

### 6.6 IPC 契约

```text
mediaMerge.selectFiles       打开图片 / 视频多选对话框
mediaMerge.selectDirectory   选择输出目录
mediaMerge.buildPlan         校验并生成计划
mediaMerge.start             创建后台任务并返回 jobId
mediaMerge.cancel            请求取消任务
mediaMerge.progress          查询进度
mediaMerge.preview           为草稿内文件生成受限预览
mediaMerge.timeline          为草稿内视频生成抽帧时间轴
mediaMerge.waveform          为草稿内视频生成音频波形
mediaMerge.resume            从失败任务的 checkpoint 恢复
```

请求与返回包含稳定的 `jobId` 或目标路径；渲染端忽略过期响应。进度事件节流，避免高频 IPC 压垮渲染端。

### 6.7 恢复设计

每个可恢复任务拥有独立工作区：

```text
workspace
├── manifest.json             计划指纹、输入状态、阶段、输出路径
├── layer-00000.png           图片任务图层缓存
└── segment-00000.mp4         视频任务分段缓存
```

checkpoint 与 manifest 必须同时校验：

- 版本一致。
- 任务 ID 一致。
- 工作区路径一致。
- 首选输出路径一致。
- 阶段数量和已完成阶段一致。
- 计划指纹一致。
- 输入路径、大小、修改时间一致。

任何一项不匹配都拒绝恢复，避免把旧分段拼入新计划。恢复时已完成的图片图层或视频分段直接复用，未完成阶段重新执行，最终重新合成并原子重命名。

## 7. 安全与失败边界

- 不修改源文件。
- 不覆盖输出文件，自动追加 `-1`、`-2`。
- 输出临时文件放在输出目录附近，成功后原子重命名。
- 用户取消或不可恢复失败时清理临时文件和工作区。
- 执行前重新 `stat` 输入，发现缺失或修改时间变化即失败。
- FFmpeg 参数数组传递，路径只传给子进程，不拼接命令解释器。
- 输出目录必须显式选择，不写入隐藏目录。
- 任务失败不能留下假装成功的输出文件。
- 内置 FFmpeg 和 FFprobe 只用于本模块媒体处理，不用于执行任意用户命令。

## 8. 验收标准

### 8.1 图片

- 3 张不同宽度图片按纵向布局输出，宽度等于设置值，顺序与列表一致。
- 横向布局输出高度等于设置值，顺序与列表一致。
- 网格布局列数、间距和行内顺序正确。
- PNG 透明背景不变成黑色。
- 超过尺寸或像素限制时执行前失败并给出建议。
- 输出同名时自动追加序号。
- 取消后没有临时文件、图层工作区和半成品。

### 8.2 视频

- 3 个不同分辨率 MP4 输出一个可播放 MP4。
- 每个视频头尾裁剪生效，总时长约等于各剩余时长之和。
- 交叉淡化生效，输出时长扣除转场重叠。
- 单素材音量、静音、淡入淡出生效。
- 部分无音频素材在保留音频输出时自动补静音轨。
- 边预览边调整裁剪时界面不阻塞。
- 快速流复制在不兼容或与音频调整互斥时返回明确错误或提示。
- 取消后没有半成品输出。
- 合并期间切换页面不中断任务。

### 8.3 执行与恢复

- 混合图片和视频时无法进入下一步。
- 规则排序后列表顺序与计划顺序一致。
- 批量应用不覆盖推荐范围内的自定义裁剪。
- 应用到全部覆盖裁剪值但保留单素材音频设置。
- 执行摘要中的数量、路径、时长和尺寸与实际计划一致。
- 任务中心能查看失败原因、断点阶段和输出信息。
- checkpoint 或 manifest 不匹配时拒绝恢复。
- 可恢复任务恢复后不重复生成已完成图层或分段。

## 10. 修改计划

本节只记录 2026-09-23 核对后还要改的内容。每一条都先说明现状，再写改动、原因、目标和要解决的问题。实现时按 10.1 到 10.8 的顺序做；10.9 到 10.12 是主流程稳定之后再加的实用能力，不插到前面。

不在本计划内：不改搜索输入助手，不把合并做成通用剪辑器，不加字幕、贴纸、滤镜、多音轨和自动推荐素材。

### 10.1 修正整段播放和片段切换

- 改什么：第三步拼接预览的播放状态机。色块单击只定位，不改变「整段 / 当前片段」。选中「当前片段」后，视频或图片走到该段结尾必须暂停，不能把时间拨到下一段。图片段结束、视频换源、拖动色块，都不能把正在播放写成暂停。
- 为什么改：图片定时器现在会拨到 `timelineEnd + 0.01`，这个时间已经属于下一段。视频切到图片时，`pause()` 发生在界面状态更新之前，暂停判断仍拿着上一段视频，于是把整段播放停掉。用户必须再点一次播放，而且「当前片段」名不副实。
- 目标：整段播放从第一段连续走到最后一段，经过图片也不停。当前片段播放只覆盖选中的那一段，结束后停在该段末尾。拖动色块、拖动播放进度都不改变这个范围。
- 解决的问题：视频接到图片就暂停；已经切到当前片段仍继续往下播；拖动后要手动恢复播放。

### 10.2 预览换源不再整页重载

- 改什么：片段地址、时长和播放位置分开保存。只有素材集合变化才重新探测；调整顺序、裁剪、图片停留时间时，保留已经读到的时长，只移动时间轴。换片段时能复用已打开的视频元素，不把整个播放器拆掉重建。
- 为什么改：现在时长探测绑在整份素材列表上，顺序或裁剪一变就清空进度，状态回到「正在读取片段时长」。每次更换 `video.src` 都会让解码器重启，画面黑一下，用户感觉软件闪了一下。
- 目标：已读过的片段不再重复探测。切换片段时画面保持上一帧，直到新片段可播放。几十段、几百段只优先读取当前页附近的时长，其余在后台补齐。
- 解决的问题：一切换就闪、一切换就重新读取；素材多时第三步长时间停在读取状态，看不到可操作的预览。

### 10.3 单个片段预览失败不能拖垮整段

- 改什么：预览失败按片段记录。浏览器不能直接播放的文件，用内置 FFmpeg 生成仅供预览的 H.264 短代理，成片仍按用户选择的格式编码。代理只覆盖当前片段和相邻片段，不提前转完所有文件。
- 为什么改：预览现在把原文件直接交给 Chromium。MP4、WebM 比较稳，MKV、AVI、TS、WMV、HEVC 经常失败。一个文件失败会把整段预览标成「当前格式无法预览」，后面能播的片段也不显示。
- 目标：能直接播的文件立即播放。不能直接播的文件显示「正在准备预览」，准备好后接入同一条时间轴。某个文件损坏时，只跳过该段并标出文件名，其余段落继续预览。
- 解决的问题：一种输入格式不能预览就导致全部黑屏；用户无法判断是文件坏了，还是程序把整段判失败了。

### 10.4 图片预览改成真实合成结果

- 改什么：第三步图片预览不再用 CSS 把原图摆在一起。由主进程按当前布局、宽度或高度、间距、背景和 EXIF 方向生成一张缩小合成图，设置变化后替换这张图。超过预览体积的原图也走缩小图，不把整张原图读进页面。
- 为什么改：当前预览固定大约 220px 宽，不按统一宽度、统一高度、间距和背景重采样。大于 8MB 的图只显示占位。执行时 sharp 会按 EXIF 旋转，预览不一定旋转，方向和成片可能相反。
- 目标：预览上的顺序、比例、间距、底色和方向与即将输出的图片一致，只是分辨率更低。尺寸或像素超限时，预览区直接显示原因，不等到点击开始合并。
- 解决的问题：改了布局、宽度、格式、背景后看不出真实结果；大图没有预览；预览方向和导出方向不一致。

### 10.5 允许单张图片导出

- 改什么：图片任务最少一张，不再要求两张。单张走同一套输出设置，可以改变宽度或高度、格式和背景。视频任务仍可包含图片；图片任务仍不能加入视频。
- 为什么改：计划校验把图片少于两张直接拒绝。实际使用里，单张图片经常只需要放大、改成 PNG/WebP，或者铺成白底、透明底，不应该被迫找第二张图。
- 目标：一张图片能生成新的输出文件，不改源文件。两张及以上仍按纵向、横向或网格合成。
- 解决的问题：只想处理一张图片时无法进入合并，也无法完成放大、改格式和改背景。

### 10.6 修正输出设置校验

- 改什么：数字框清空或输入非法值时保留上一个合法值，不把 `0` 写进计划。横向布局只校验统一高度，纵向和网格只校验统一宽度；另一项保留默认值，但不参与当前布局的报错。错误显示在对应输入框下，并说明当前值。
- 为什么改：1080 在 16 到 8192 之间，本身合法。输入框被清空时会变成 `0`，`0` 被当成有效数字，生成计划才报「统一宽度必须在 16 到 8192 之间」。横向布局界面只显示高度，校验却仍检查宽度。
- 目标：合法默认值永远可以生成计划。用户输入超出范围时，提示指向实际出错的那一项，不出现与界面无关的宽度错误。
- 解决的问题：默认 1080 仍报宽度非法；改横向高度时被宽度校验拦住；用户不知道是哪个输入框导致失败。

### 10.7 统一可导入格式

- 改什么：搜索导入、文件选择器、预览协议和核心库使用同一份图片、视频扩展名。HEIC、TIFF 等核心库已经识别的图片，桌面端也要能选、能预览、能进入图片合并；桌面端已经接受的视频扩展名，计划校验也要接受。
- 为什么改：核心库把 HEIC、TIFF 当图片，桌面选择器和预览协议不认。搜索导入和手动添加会得到不同结果，同一文件可能能进列表但不能预览，或者预览和执行对类型判断不一致。
- 目标：一个扩展名在导入、预览、计划、执行四处的结论一致。不支持的格式在选择时就被过滤，并给出扩展名，而不是进到第三步才失败。
- 解决的问题：同一文件因入口不同而表现不同；部分图片能被扫描识别，却不能加入合并。

### 10.8 合并执行移出界面主进程

- 改什么：图片合成、视频探测、抽帧、波形和 FFmpeg 编码放到独立 Worker。界面进程只负责编辑、发送计划和接收进度。开始前给出输出尺寸或时长、预计阶段数、是否可用快速流复制，以及不能用的具体原因。
- 为什么改：计划、sharp 合成和 FFmpeg 目前跑在 Electron 主进程。文件一多，探测和重编码会堵住窗口移动、任务进度和其他页面。图片图层还会先解码成无压缩 PNG 再进内存，长图可能在达到 1 亿像素上限前就内存不足。
- 目标：合并运行时窗口仍可切换页签、取消任务和查看进度。取消立即停止 Worker。失败保留已完成阶段，成功后仍原子重命名，不留下半成品冒充结果。
- 解决的问题：执行或读取媒体时整个程序未响应；长图内存占用不可控；快速流复制要等执行失败才知道不能用。

### 10.9 视频画面尺寸可选择

- 改什么：重编码增加三种画面尺寸：按最大素材、按第一条素材、限制在 1080p 以内。默认仍按最大素材，保证现有任务结果不变。小于目标尺寸的画面继续黑边居中，不裁掉内容。
- 为什么改：现在输出宽高取所有素材的最大值。竖视频混横视频时，小画面周围有大块黑边，编码分辨率也被最大的素材拉高，时间变长、文件变大。
- 目标：用户能在执行前看到目标分辨率。限制在 1080p 时，长边不超过 1920、短边不超过 1080，并保持偶数尺寸。
- 解决的问题：混合方向或混合分辨率时成片又大又空，编码也没有必要地变慢。

### 10.10 预览声音和动效与成片一致

- 改什么：预览静音按钮仍只影响预览。除此之外，预览要使用全局音量、单段音量、单段静音和淡入淡出。图片的淡入淡出、缓慢放大、缓慢缩小、左右平移要在预览里按停留时间演示，不能只在导出滤镜里存在。
- 为什么改：预览静音是本地状态，不读取成片音频设置；转场用的第二路画面还被固定静音。图片动效只写在 FFmpeg 滤镜里，预览一直是静止图，用户无法在导出前确认效果。
- 目标：预览里听到的相对音量和看到的图片动效，与导出参数一致。预览静音不会改写任务里的音频设置。
- 解决的问题：预览有声音但成片被静音，或预览无声音但成片保留原声；图片动效必须等导出后才知道对不对。

### 10.11 批量图片参数和输出命名

- 改什么：视频任务里的图片增加「应用到全部」：停留时间和出现方式可批量设置，单张仍可改回自定义。输出文件名提供可选模板，包含首个文件名、数量和日期；默认名称保持现在的 `nestify-merge`。完成后提供「打开所在目录」。
- 为什么改：每张图片都要单独改停留时间和出现方式，素材一多就没有可操作性。输出名和完成后的去向也要用户自己处理，批量合并时重复操作多。
- 目标：批量值立即反映到未自定义的图片上，已自定义的图片不被覆盖。模板生成的文件名仍经过现有非法字符和扩展名校验，不能覆盖输入文件。
- 解决的问题：大量图片加入视频时逐张设置太慢；每次都要手工命名，完成后还要自己找输出目录。

### 10.12 成片章节和响度归一

- 改什么：MP4、MOV、MKV 导出时，按最终片段边界写入章节，章节名使用源文件名。另增加可选的整体响度归一，默认关闭。快速流复制保持原样，不写需要重编码或改音频的处理。
- 为什么改：几十段合成后，播放器里只有一条进度，很难回到某一个源文件。各段音量差异大时，只靠逐段音量也不如一次整体归一直接。
- 目标：支持章节的播放器能看到并跳到每个源片段。开启响度归一后只调整输出音量，不改变画面、裁剪和顺序。关闭时输出与现在一致。
- 解决的问题：多段合成后难以定位来源；音量忽大忽小时没有一个安全的整体处理开关。
