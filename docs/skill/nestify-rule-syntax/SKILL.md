# Nestify 规则语法

当用户询问 Nestify 中如何表达文件管理需求，或要求 AI 生成搜索条件、改名模板、整理规则、改名规则组筛选条件时，使用本 skill。

## 使用流程

1. 先判断输出场景，再生成语法：
   - **搜索/筛选**：生成 `kind:dir` 这类字段条件和布尔表达式。
   - **改名模板**：生成包含 `{field}` 或 `{field.chain()}` 的新名称模板。
   - **改名规则组筛选**：生成改名第三步某一个规则组使用的搜索/规则表达式。
   - **整理规则**：生成匹配表达式，并配合应用中选择的整理动作或目标模板。
2. 确认用户要匹配的字符来源：
   - `folder_name` 是当前目录自身的名称，文件上的值为空。
   - `file_name` 是当前文件的完整名称，包含扩展名，目录上的值为空。
   - `name`/`stem` 是文件不含扩展名的名称；对目录来说就是目录名称。
   - `filename` 是当前条目的完整名称。
   - `parent`、`grandparent`、`path`、`relPath` 是位置相关字段。
3. 明确翻译逻辑。使用 `AND`、`OR`、`NOT` 和括号；遇到嵌套的“并且/或者”需求时不要依赖书写顺序猜优先级。
4. 始终分离“匹配”和“输出”：筛选条件决定哪些条目命中，改名模板决定命中条目的新名称。
5. 只能使用参考文档中存在的字段和函数，不要自行发明 SQL、JavaScript、Shell 或未实现的函数语法。
6. 输出最终表达式或模板、简短中文解释，以及一个命中示例。用户说“前面几位”等有歧义的描述时，要说明采用的假设。

## 重要语法规则

- 搜索字段使用 `field:value`，例如 `kind:dir`、`folder_name:电影`、`size:>10MB`。普通关键词直接输入，包含空格的短语使用双引号，例如 `"hello world"`；不要生成 `text:值` 或 `phrase:值`。
- 布尔表达式支持 `AND`、`OR`、`NOT`、一元排除符 `-` 和嵌套括号 `()`；也支持全角括号。
- 不加操作符的普通文本会保持搜索兼容行为，通常按 OR 处理；字段筛选条件通常按 AND 处理。AI 生成规则时应优先写出明确的操作符和括号。
- 规则函数谓词写成 `field.function('argument')`，例如 `folder_name.contains('www')` 或 `folder_name.match('^[^-]+-.*www.*')`。
- 变换后的值可以用 `:expected` 比较，例如 `folder_name.slice(0, 2):AB` 或 `folder_name.after('-'):www`。
- 规则组中多个备选条件要用 `OR` 分组，例如 `kind:dir AND (folder_name:电影 OR folder_name:电视剧)`。
- 改名规则组会与第二步外层筛选合并。多个规则组是“或者”关系，重叠命中时按规则组顺序分配。
- 改名模板使用花括号，例如 `{name}`、`{name.after('-').trim()}{ext}`。不要把 `AND`、`OR` 或 `field:value` 写进改名模板。
- 目录改名模板通常不加 `{ext}`；文件改名模板如果要保留扩展名，应追加 `{ext}`。
- `match()` 在不同场景含义不同：搜索/规则筛选中用于测试正则，改名模板中用于返回第一个捕获组；没有捕获组时返回完整匹配。
- 函数参数可用单引号或双引号包裹；参数中的引号或反斜杠需要转义。

## 标准示例

需求：“只匹配文件夹，名称前面有一段不包含短横线的内容，后面有短横线，并且名称包含 `www`。”

```text
kind:dir AND folder_name.match('^[^-]+-.*www.*')
```

如果改名结果要去掉第一个 `-` 及其前面的内容，只保留后面的内容：

```text
{name.after('-').trim()}
```

生成复杂语法前，请阅读 [references/syntax-reference.md](references/syntax-reference.md)，其中包含完整字段、函数、模板、规则组和错误排查参考。

用户只询问语法时，不要擅自执行扫描、改名、移动、删除或其他文件操作。只有用户另行明确要求执行时，才可以进入实际操作流程。
